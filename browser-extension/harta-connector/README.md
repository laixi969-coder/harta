# Harta 浏览器连接器 0.2.0

1. 在 Chrome / Edge 扩展程序管理页加载本目录。已安装 0.1.0 的用户先替换解压目录，再点击扩展的重新加载。
2. 在该浏览器个人资料中登录抖音或小红书。不同账号用不同浏览器个人资料。平台密码、Cookie、验证码不上传 Harta。
3. Harta「平台账号」登记账号、生成配对码，在扩展弹窗输入 Harta 地址和配对码。配对码十分钟一次性，连接三十天，可撤销。
4. Harta「平台执行」绑定自己真实的平台主页。执行时会再次从平台登录入口核对用户 ID，不能只凭昵称执行。
5. 在扩展勾选「执行 Harta 中已确认的发布、消息和已启用自动回复规则」。如需后台检查，另开启自动检查任务。关闭实际执行开关后不领取新发送任务；已经提交的操作不能撤回。

## 操作

- 读取：Harta 主动获客 → 目标账号 → 作品 → 评论。只处理页面实际加载内容。
- 发布：平台执行 → 发布内容 → 上传 MP4 成片（抖音）或图片（小红书）→ 填写标题正文 → 选择公开或仅自己可见 → 确认发布。每文件及单次总素材最多 80 MB。不是把脚本冒充成片。
- 私信／评论：客户跟进准备好具体原文 → 平台执行「发送消息」核对接收人及账号 → 确认发送。需要真实用户 ID，回复评论需要原评论 ID。按浏览器页面实际控件提交。
- 自动回复：平台执行 → 自动回复 → 指定自己作品或一个私信对象的主页 → 设置关键词和固定回复 → 开启。第一轮只建立历史基线，后续新消息匹配时自动发送。未匹配的新消息同步为咨询；对方拒绝联系、人工接管、超出每小时上限时不自动发。
- 回执：只有读取到新增平台消息 ID 与相符的发送人／原文，才记为「平台回读成功」。发布成功页没有作品 ID 时记为「平台已受理」。点击后超时记为「结果不明」，不自动重发，并暂停对应自动回复规则。

## 当前验收边界

已完成隔离页面的发布、私信、评论提交与回读测试，以及后端权限、取消、重复提交、隐私范围变化和自动回复基线测试。
抖音真实账号登录验收待用户继续；当前浏览器访问抖音曾返回 ERR_CONNECTION_CLOSED。平台 DOM 可能随账号、版本变化，需要实际登录后校准。无法唯一识别控件、接收人或隐私范围时返回明确错误，不能把未执行的动作标成功。
小红书未做真实发送验收。用户本轮指定先验收抖音。

不绕过验证码，不调用逆向签名接口，不代用户批量养号或群发。执行器只领取明确确认的操作和已启用规则产生的任务。
