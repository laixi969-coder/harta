## 这个台子是给谁的

许多销售对许多客户，彼此看不见。客户进门是两种并列的活，不是一条漏斗的前后两截。

有些客户是已经存在的、已经在合作的——不需要先判断，建档就选存量，当天出内容、拿线索、引流。

有些客户是拓新——根据给到的资料出一份建议报告：该不该打、截谁、缺口、主战场、还缺什么。没看过资料就只出侦察（提问，不下诊断）。拓新成交了也还是拓新，不会被系统偷偷改成存量。

发出去的东西点得出有没有回音，下一批顺着回音出。负责人隔一阵看一眼全组哪条猎场真有回音——只有数，不拆到人。

## 每天怎么用

打开「今天」。第一行说清：存量几家、今天还差几家没出内容，拓新谁资料齐了该出判断，并点名先做哪一家。

下面是两列待办。左边是存量今天该发的，右边是拓新该判断的。默认展开最急的那一家：存量看到的是今日内容，复制就能发；拓新看到的是判断报告，打开甲方页给对方看。点另一家，正文跟着换。不再把整页钉死在「先用一位」上。

发完点有回音 / 没反应。台账该记还记。记成交只是记一笔账，客户种类不动——真要把一家拓新改成存量，人自己在客户页改，系统不许替他做这个决定。

第一周没有反馈，就不说上次怎样；「上次有效」整块不出现。今天待办都做完了，才把上次有效顶上来，让人去记回音，而不是空欢喜。

## 两条活的规矩

- **拓新 = 判断报告。** 没看过客户的东西（没留官网、没贴材料）只出侦察——赛道格局加精准提问，不出诊断。看过才出判断。判断里可以带最多 3 条样例，用来说明「如果做，长这样」，不是给销售今天去发的库存。
- **存量 = 内容批次。** 建档就可以出，不经过判断，也不要求这家名下先有一份报告。每次点击独立生成 50 条文案，四类平台各至少 20 条外壳；同一天可以连续出多批。吃最近几批的回音；没有回音就吃猎场包，并如实说没依据。
- **种类由人选定，不由结果推断。** 建档时必选拓新或存量。事后可改。成交、有回音、出过判断，都不自动改。
- **历史旧档只读。** 以前出过的快档 / 全档 / 补给还在客户名下，打开能看当时给过什么，不再按那套升级路径新出。存量客户可以一份判断都没有。
- **已有客户未标明种类的，不进两列待办。** 打开后选一次才能出活。不要默认成拓新，否则会逼已经在合作的客户再走一遍判断。
- **超管本子里那三个演示客户**是给人看样子的，台账里的演示行带着标记，不进任何统计。

## 猎场

猎场就是行业包。策展的在 vendor/hiccai-pitch/industries，遇到新行业选「其他行业」现场长一份存 data/industries，长出来的标 D 级，同名时策展的赢。红线词表跟着行业包走，交付前检查分「发不出去」（硬限制）和「会有代价」（建议）两档，软数字不许当红线。医药等高风险包的硬限制不变。

## 已经想过但没做的

- 销售互查、拿别人的效果给自己排序：不能。
- 没反馈就写效果很好：不能。
- 可追名单铺满文案、不挂客户的通用条：否。
- 拓新每天强制出可发内容：否。
- 存量再走「先用一位看整份获客档」：否。
- 把判断报告做成 15 条今日库存：否。
- 把存量当成拓新成交后的下一站：否。已经存在的客户不需要先判断。
- 成交自动改种类：否。
- 存量必须先有判断报告才能出今日：否。
- 拆成两个独立台子：先不合。同一销售同一早上，一张桌子两列待办。真觉得抢，再拆。
- 猎场独立成册、哪些有效独立页、存量周报给甲方：第二版。
- 全组页拆到人：否——负责人看数可以，看谁的不行。
- 暖象牙纸 + 黄铜档案室：否。要新配色。

## 给实现方（不熟悉本规范的 AI 或开发，照这段做即可）

- **网页，电脑浏览器。** 默认落地「今天」。hook 是第一行。正在出活/失败/没出过各有说法，不许空白或假数。
- **L1 必须是双列待办，不是漏斗，不是一张客户表，也不是整页钉死在一位客户的档全文。** 左列=存量今日未出，右列=拓新该判断（资料齐了待出 / 资料未齐要补）。已完成的从待办拿掉。不要画「拓新 → 成交 → 存量」的阶段条。
- **Customer.track** 是种类，不是阶段。建档时必选。只有人能改。台账成交、有回音、出过 Pack，都不得改 track。
- **出活分流：** track=拓新 → 出判断（Pack.tier 侦察/判断）；track=存量 → 出今日（TodayDrop）。不要给存量出判断当必经步骤，不要给拓新出每日库存。存量出今日不检查是否有 Pack。
- **判断报告闸门：** 没读到资料只出侦察（提问，无诊断）。有资料才出判断。样例 ≤3 条，不是 ≥15 条。四平台铺满库存那套闸门只留给 TodayDrop。
- **内容批次闸门：** 每次点击都独立生成 50 条文案，四类平台各 ≥20 条外壳；铺不满作废重跑。同一客户同一天可反复再出一批（batch），不覆盖前一批，也不按自然日限次数。没有历史反馈时用猎场包，并在界面如实说没依据。
- **历史 Pack：** 旧的快/全/补给档只读展示，不按旧升级路径（有反应补分镜、付钱补货）新出。补分镜不再作为拓新升级；短视频是存量今日内容的一种平台，不是一份独立「全档」。
- **已有客户迁移：** 未标明 track 的不进待办、不出活，打开客户页必须先选拓新或存量。不要默认成拓新。
- **反馈：** workspace 级字典，key 为 `<packOrDropId>-<组名>-<行号>`，值 replied/dead。只对已发的显示「有回音 / 没反应」。
- **台账回写：** POST /api/ledger 带 line 字段；result ∈ {问了价, 有兴趣, 成交} 且 line 真实存在于该客户名下的产出时，feedback[line] = "replied"。成交不改 track。别的 key 一律不写。
- **上次有效：** 跨批次找——把该销售所有客户的所有 Pack 和 TodayDrop 按日期倒序，第一份有 replied 的就是「上次」；当前这份才说「已往前排」，更早的说「哪天那批」。没有任何回音时整块隐藏。今日还有待办时，不把它顶到 hook 正下方。
- **补给 / 出今日：** 吃最近几批（最多三批）的反馈；有反馈时强制 ≥25% 的「试」字头新方向组，不然整份作废。没反馈时平铺并如实说没依据。
- **就地改：** 改文案存 edits 不覆盖原句（原句留给对比），复制和甲方页拿改后那版，改完立刻重跑检查。
- **甲方页：** 只挂判断报告。每日内容默认复制去发，不自动生成 /p/<token>。页内禁止 AI。
- **全组页：** GET /api/overview，仅超管。聚合各猎场的 有回音/问价/成交 + 最近原话 + 今日双轨计数（存量出了几家、拓新出了几份判断）；demo 台账行不进数；不返回任何销售个人明细给非管理员。
- **隔离：** 反馈、汇总、排序都不得串销售。超管也只看聚合数。
- **不要做成打分表、星级、问卷。** 一下下就完。
- **空状态 day_1。** 冷青纸面，有回音只盖一枚朱红点。不要暖象牙、不要黄铜、不要档案室。DESIGN.md 里的旧四材料（纸/墨/黄铜/漆木）作废，换新 token 后再改 css。
- **现有界面会作废的屏幕：** 全站配色与信头（login / 今天 / 客户 / 包裹 / 台账 / 全组 / 设置 / 甲方页）。双列待办的结构保留，只换纸色和印记。不要重做成仪表盘或卡片墙。
