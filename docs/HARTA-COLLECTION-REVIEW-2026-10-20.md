# Harta 采集与人工发送修复

本次检核覆盖 Harta 的采集、作品库、评论、线索、数据源设置与平台执行接口。没有解除受限账号，也没有执行真实消息发送或付费 API 采集。

## 从实际行为检查

1. 任务为零条且 Chrome 没有启动时，应诊断启动失败。抖音不再清空 Playwright 默认参数，启动最多等待 30 秒，保留 Harta 的可执行路径和 headless 配置。使用新临时配置实测 Chrome 启动与可见验证码检查通过（约 630 ms）。
2. 生成内容不等于授权平台执行。宿主的托管浏览器、队列领取/提交许可、自动回复，以及内嵌引擎的发送、代填和发布均已关闭。后台私信轮询不再执行；旧未提交任务取消，已提交但缺少回执的任务标为 unknown，历史已发送结果不改写。草稿、复制、素材导出和人工登记仍保留。
3. 采集目标应可调整，且不同于请求预算。搜索、关键词选样、每篇评论均支持 1–100；指定作品链接保持同平台最多 10 条。去重、平台分页、请求预算和无匹配结果可能导致实际条数较少，不承诺凑满。
4. 数据来源应隔离。小红书可选 TikHub / RedFox；抖音独立选择浏览器、TikHub、RedFox 或已有高级 HTTP。配置与密钥在当前用户的当前业务中保存；密钥不回传，切换供应商/密钥会隔离缓存，API 失败不自动回退到浏览器。
5. 分类应由来源证据恢复。作品库和评论选择器按平台、采集主题筛选，已有任务恢复关键词归属，无归属的标记未分类；保留当前任务、作品类型和真实/演示范围。

## 额外缺陷

- 登录曾经有效不能证明当前可以读取。先检查所有验证码匹配节点，防止隐藏旧节点遮蔽活动验证框；身份响应不能覆盖 challenge，检查失败不能沿用 ready。
- API 初始化异常原本可能发生在任务清理块之外，使运行锁不释放；已移入清理范围。临时数据库损坏密钥的回归验证任务失败后仍可保存新配置。
- 原分页只检查相邻重复游标；现在同时拦截 A → B → A，防止重复付费请求。
- 历史作品缺少 tags 时，线索计算可能使整个 state 请求失败；服务端按空标签处理。
- API 可用性不再依赖 Chrome 是否安装。

## API 范围

- TikHub：小红书与抖音的搜索、详情、评论，保留接口返回的附带回复，不声称取得所有楼中楼。
- RedFox：小红书搜索、详情及异步一级评论；异步任务保留标识以便继续，不重复提交不确定的收费任务。
- RedFox 抖音：当前只接搜索和详情。评论流程在发出请求前明确拒绝；不会换供应商或悄悄扣费。
- API 测试按钮明确提示可能收费；保存配置本身不发起采集。具体接口覆盖、余额和价格以供应商为准。

文档：[TikHub API](https://api.tikhub.io/)、[RedFox 抖音](https://redfox.hk/apis/douyin)、[RedFox 小红书](https://redfox.hk/apis/xiaohongshu)。
