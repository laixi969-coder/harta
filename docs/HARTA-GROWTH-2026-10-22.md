# Harta 目标驱动优化 · 2026-10-22

目标：用更少的请求、操作和等待，找到值得核实的需求，生成有依据的内容，并记录可核对的结果。发送和发布由用户完成，自动托管、回复和代发不会恢复。

## 本轮落地范围

| 原清单 | 实现与使用入口 |
|---|---|
| 1 真实数据源验收 | 平台账号 → 真实数据源验收；主动触发，最多 5 次请求，记录搜索、详情、评论与分页各自状态。无下一页标为未验证，异步任务标为等待；不把空结果或未支持能力冒充全链路通过。 |
| 2 流程与每日预算 | 平台账号 → 业务请求预算；API 默认每流程 60 次、每天 200 次，两平台与高级 HTTP 共用，翻页和详情累计。评论复核模型每日默认 100 次，单独计量。缓存不扣减，已发出失败请求保守计数；恢复不会清零，UTC 零点重置每日额度。此计量不覆盖内容生成与销售草稿模型调用，也不是货币账单。 |
| 3 数量解释 | 任务日志显示目标、返回、重复、超目标、保存与请求次数，以及目标已达、来源耗尽、缓存、暂停或异常；老记录明确未记录，不补造数字。 |
| 4 小批验证 | 批量获客默认关键词模式与 10 条搜索；先看作品样本，再人工继续评论采样。可选择已有产品名作为关键词；参数仍可调整至 100。 |
| 5 业务匹配 | 批量获客增加需求词、排除词与服务范围；仅按原文筛选。地域未知保留待核实，IP 属地不用于推断居住地。修复作者身份均为空却误判作者回复的缺陷。 |
| 6 产品规则 | GOAL、PRD、README 与历史接入说明增加现行人工执行规则；旧页面不再引导自动回复或小红书浏览器采集。 |
| 7 分类与归档 | 发现作品 → 分类、归档与常用筛选：需求分类、产品标签、处理状态、批次、发表日期、归档范围；按业务保存常用筛选；批量归档、恢复、撤销，版本冲突拒绝覆盖。分类会同步到作品资料，历史图库默认隐藏归档项。 |
| 8 重复联系人 | 评论核实可明确关联同业务、同平台且身份兼容的已有联系人。联系人页提示同名记录供核实，跨平台不会按昵称自动合并。不同购买需求继续独立保留。 |
| 9 今日待办 | 统一待回复、联系人到期、购买需求到期、待开场、待核实、待发布；修复仅显示购买需求而漏掉联系人跟进的问题。 |
| 10 人工联系 | 查看原文／主页、起草、复制、人工发送登记沿用受控流程；新增无需配置智能体的“帮我起草回复”，使用已核实资料与现有销售草稿服务。复制和打开平台均不记为发送。 |
| 11 需求到内容 | 内容首页直接查看、更新已有评论痛点、对标、关键词和研究选题池，采用后进入当前业务创作方向，保留来源证据。 |
| 12 简化默认操作 | 首页围绕找机会、写内容、处理跟进；匹配条件、常用筛选、验收与服务诊断放在折叠设置；人工草稿可直接生成。 |
| 13 业务看板 | 工作台按当前业务统计作品、待核实需求、去重联系人、有发送记录的人、有来信的人、成交购买需求与成交人数。修复购买需求成交未计入的问题。未知曝光、收入与退款不记零，不从次数推断转化率。 |
| 14 轻量结果回填 | 发布效果默认先显示当前目标指标，其余指标折叠；保留统计窗口、数据来源、口径、版本快照、批量导入及重叠窗口不累加。现有人工归因继续使用，不宣称自动订单归因。 |
| 15 恢复与健康 | 平台账号 → 任务与服务状态；运行/暂停/失败状态可检查。API 保存分页游标与已读 ID，恢复同一个任务；供应商指纹变化拒绝混用。重复游标先保存有效本页再停止。浏览器/自定义 HTTP 不承诺跨会话续页，明确要求新任务。 |
| 16 备份恢复 | 本机离线工具覆盖业务 JSON、素材、SQLite 一致性快照及 API 密钥；恢复到新目录并验证哈希、数据库和密钥，拒绝覆盖、路径越界与符号链接。清空登录会话、排除浏览器/托管/OAuth 会话、关闭采集计划。 |
| 17 持续检查 | `npm run check` 运行主程序测试、采集检查、类型检查及生产构建；GitHub Actions 在 push/PR 执行，检查已提交构建产物；浏览器脚本覆盖预算隔离、分类、人工发送及响应式页面。 |

## 数据源与恢复修复

- 来源已耗尽但不足目标的结果，在有效缓存时间内复用，不为凑满而重复计费。
- RedFox 异步任务完成结果保留原始取得时间；默认复用旧任务，设置中可明确准备新批次，下一次用户采集才重新计费。
- RedFox 在本地预算、取消或密钥检查通过后才记录提交开始，避免未出网却卡在“提交结果不确定”。
- 凭证密钥丢失或损坏时拒绝启动业务数据库，不生成新密钥掩盖问题。

## 备份与恢复

先完全停止 Harta 服务及相关 worker。服务运行时维护工具会拒绝操作；更新前旧进程可能尚未使用运行锁，也必须先停止。备份目录包含敏感业务资料与 API 凭证，默认私有文件权限，保存在可信本机磁盘。

```sh
node scripts/harta-backup.mjs create /Users/caiwenbin/Harta/data /Users/caiwenbin/Harta-backup-2026-10-22 --offline
node scripts/harta-backup.mjs restore /Users/caiwenbin/Harta-backup-2026-10-22 /Users/caiwenbin/Harta-restored-data
```

恢复只接受不存在的新目标路径，不自动切换生产目录。先在隔离环境核对业务、素材、密钥及停用计划，再由管理员切换。清单哈希用于检测损坏，不用于证明备份提供者可信。无需迁移的服务缓存、日志、浏览器配置和登录会话排除。

## 验收边界

本轮真实业务中两平台均未配置供应商 Key，只检查了配置存在性，未读取或输出密钥。代码、模拟响应和隔离浏览器验收不能替代真实付费 API 验收；用户配置 Key 后，可以在“真实数据源验收”执行。接口覆盖、余额和价格仍以实际供应商为准。

备份恢复演练只使用临时业务、虚拟凭证、WAL 数据和素材，未覆盖或复制生产业务目录。未登录受限账号，未实际发送消息，未购买或调用付费数据服务。恢复后数据保留，但真实订单与平台效果仍由用户核实。
