# Harta 界面技术审查

范围：当前“今天”工作台，重点为 HPV治疗客户的100词词库、平台内容依据、导入与搜索；检查共享 CSS 和工作区返回链路。依据项目 .impeccable.md 中的销售办公场景、清晰可信品牌要求及本次用户“不依赖逐篇反馈”的要求。使用 audit 与 frontend-design 技能；不修改功能代码。

## 反模式结论

未通过严格反模式检查，但不是典型霓虹渐变式 AI 模板。实际截图中，待办区域存在外层卡片包裹内层带圆角及阴影的客户条目；内容依据又重复同样的卡片容器。重复的边框、阴影和说明文字削弱了“一个明确主操作”的层级。配色、中文字体和侧栏品牌有一致性，不应为追求风格差异推翻。

## 健康分

| 维度 | 分数 | 主要发现 |
|---|---:|---|
| 可访问性 | 2/4 | 搜索结果数量变更没有状态播报 |
| 性能 | 2/4 | 每次输入重建词库DOM；工作区返回时重算全部客户依据 |
| 响应式 | 3/4 | 390px无整页溢出；展开入口偏小，宽表阅读费力 |
| 主题 | 3/4 | 主体使用双主题token；新词库引用未定义变量 |
| 反模式 | 2/4 | 嵌套卡片与重复说明影响层级 |
| 总计 | **12/20** | **可接受，但需要针对性改进** |

共6项：P0=0、P1=1、P2=5、P3=0。优先处理搜索播报、词库渲染及主题变量，再改善窄屏阅读。分数仅适用于本次范围，不是整个产品的WCAG认证。

## 详细问题

### 1. [P1] 搜索结果数量变化未向辅助技术播报
- 位置：`js/app.js:3317`、`js/app.js:3330`；`index.html:109`、`index.html:111`。
- 类别：Accessibility。
- 证据：输入不存在的词后，summary显示“匹配0个”；结果容器没有aria-live或status区域。导入进度的独立status不会播报搜索结果。
- 影响：焦点留在搜索框的读屏用户无法及时获知搜索是否找到结果，需要手动探索下面的内容。
- 标准：WCAG 2.1/2.2 4.1.3 Status Messages（AA）。未做真实读屏软件测试；依据动态状态结构判定。
- 建议：在搜索框后增加独立、简短的polite status，播报总匹配数及展示数；不要把整个数据表设成live region。
- 建议命令：`/harden`。

### 2. [P2] 搜索逐键重建所有批次内容
- 位置：`js/app.js:3317`、`js/app.js:3325`、`js/app.js:3330`。
- 类别：Performance。
- 证据：每次input执行全部批次过滤并innerHTML替换，包含所有主题描述及每批前100行的完整来源；闭合details也预先构建内容。
- 影响：大词库输入时增加主线程工作与DOM分配，重建还会丢弃用户手动展开的状态（空查询按模板默认闭合）。未对浏览器输入延迟作定量基准，不声称已经卡顿。
- 标准：无直接WCAG判定。
- 建议：保留批次节点和展开状态；搜索只更新匹配行及计数，按需构建展开内容，必要时增加短防抖。
- 建议命令：`/optimize`。

### 3. [P2] 工作区轮询附带同步重算所有客户的内容依据
- 位置：`lib/workspace.mjs:102`、`lib/keyword-opportunities.mjs:43`、`js/app.js:2299`。
- 类别：Performance。
- 证据：publicWorkspace对所有客户调用buildKeywordOpportunities；任务轮询取完整工作区。合成单平台测试：100词约9ms，10000词约76ms，单个依据对象约41KB。仅一次本机样本，非生产延迟承诺。
- 影响：词库和客户数量增长时，同步计算占用Node事件循环；轮询重复传输未变化的业务资料和依据。
- 标准：无直接WCAG判定。
- 建议：按客户资料与词库版本缓存派生依据；任务状态接口只返回变化状态，打开客户时才加载完整词库。
- 建议命令：`/optimize`。

### 4. [P2] 词库边框使用未定义主题变量
- 位置：`css/app.css:2344`、`css/app.css:2348`。
- 类别：Theming。
- 证据：两处使用var(--line,#ddd)，根元素--line实测为空；浅色、深色边框均为rgb(221,221,221)，深色卡片背景则正确切成oklch(0.185 0.018 200)。
- 影响：深色界面的边框明显过亮，表格横线与整体主题失去一致性。
- 标准：主题一致性问题；不凭此宣称文字对比度违规。
- 建议：使用已有--border，必要时新增明确的表格分隔token并提供双主题值。
- 建议命令：`/normalize`。

### 5. [P2] 窄屏词库可读但操作与横向查看不够友好
- 位置：`css/app.css:2345`、`css/app.css:2346`、`css/app.css:2347`；`js/app.js:3325`。
- 类别：Responsive / Accessibility。
- 证据：390px视口整页scrollWidth为379px，无整页溢出；表格容器clientWidth约263px，内部scrollWidth为680px。多处summary高度25.59px。滚动容器没有可访问名称及显式tabindex。
- 影响：手指点击展开入口容错较低；查看右侧原始数据需频繁横向拖动，滚动区域目的不明确。
- 标准：44px为本次技能的触控质量目标，不把约26px自动判为WCAG 2.2 AA 24px最小目标失败；数据表允许二维滚动，不能仅凭横向滚动判1.4.10失败。现代Chrome可能自动使滚动区可聚焦，尚未跨浏览器验证键盘障碍。
- 建议：summary最小触控高度44px；窄屏把来源放入行内详情，保留关键词和意图；为横向滚动区加名称和滚动提示，并验证键盘访问。
- 建议命令：`/adapt`。

### 6. [P2] 嵌套卡片和重复说明争夺主操作注意力
- 位置：`css/app.css:579`、`css/app.css:1204`；`js/app.js:3363`；`index.html:98`。
- 类别：Anti-Pattern。
- 证据：实际桌面截图中待办外框内仍有客户圆角阴影块；优先选题模板在已有card内重复生成keyword-batch容器。多条候选逐条重复相同咨询/证据提醒。
- 影响：销售需要扫描大量边界与重复句子才能找到当前业务的下一步动作；与设计上下文禁止卡片套卡片的原则相冲突。
- 标准：产品信息层级问题，无直接WCAG判定。
- 建议：内部改为分隔行，共同说明上移一次，单条仅保留需求、特有缺口与动作。
- 建议命令：`/distill`、`/arrange`。

## 系统性模式

新增词库组件没有完全沿用既有组件规范：主题token、44px触控目标、动态状态播报和滚动区语义未形成一致约束。数据层与展示层都倾向全量处理，适合小数据但需要为词库增长拆分读取及渲染路径。

## 应保留的优点

- 中文字体、青灰/青绿双主题和品牌侧栏符合已确认的设计方向。
- 主要表单均有for/id标签，导入状态与toast已有live status，可复用到搜索。
- 使用原生details/summary，已有全局focus-visible和prefers-reduced-motion支持。
- 常规按钮设定min-height:44px；移动断点实际将主要区域变为单列。
- 词库表格把溢出限制在局部，没有拖宽整个390px页面。
- 未发现必要性不明的动画库；CSS交互主要使用颜色、opacity和transform。浏览器JS总计约180KB、主CSS约67KB（未压缩文件大小，不等于传输体积）。
- 来源、未知日期、模型推断与原始关键词有明确区分。

## 推荐执行顺序

1. [P1] `/harden`：补搜索状态播报及辅助技术访问验证。
2. [P2] `/optimize`：增量渲染词库，缓存内容依据，缩小轮询响应。
3. [P2] `/normalize`：统一词库边框token。
4. [P2] `/adapt`：增大展开目标并调整窄屏词库阅读。
5. [P2] `/distill`：消除重复提示；配合`/arrange`展平内部层级。
6. `/polish`：最后统一间距、分隔线与焦点状态。

可逐项、全部一起或按任意顺序执行；修复后重跑`/audit`复核评分。

## 未覆盖

未运行真实屏幕阅读器、全站颜色对比度自动扫描、200%文字缩放、全部浏览器及所有设置页；不将这些未测项记成通过。未修改业务代码、历史内容或关键词数据。

## 本轮修复与复核

上述6项已针对性修复：

- 搜索计数使用独立polite status；120ms防抖，保留批次节点和展开状态，仅更新结果行。
- 批次折叠时不创建明细；展开后每批最多挂载100行，原始来源按需展开。
- 内容依据使用有容量上限、60秒TTL的内容指纹缓存，资料变化立即失效，输出深拷贝避免串改。任务轮询改用认证后的`/api/jobs`，完成时再读取完整工作区；完整读取失败会继续重试。
- 词库边框统一使用`--border`，清除嵌套卡片阴影和重复的共用提示。
- 390px词库按条目展示，原始数据可展开；滚动区域有名称与键盘焦点，展开控件最小44px。

验证：33个测试文件、257项测试通过。真实Chrome中，100词折叠时DOM表格行数为0；展开为100；搜索“多少钱”显示3行且status播报3个匹配。390px时词库容器clientWidth=scrollWidth=297px，summary高45.59px；768px整页无水平溢出。深色边框实测使用oklch主题token；控制台未见error。未登录`/api/jobs`返回401。测试后恢复浅色、原视口并清空临时搜索。

没有进行物理手机、真实读屏软件和全站WCAG认证；不据此宣称全平台完美。原评分保留为修复前基线，下一次完整audit再重新计分。
