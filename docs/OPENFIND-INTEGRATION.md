# OpenFind 融入 Harta

更新：2026-10-17。内置上游 [OpenFind](https://github.com/laixi969-coder/openfind/tree/b98978dda3c5d51e2476646bde4349b050e6fcfa) 的实时浏览器搜索、评论采集、缓存、限额与工作流，固定版本 `b98978dda3c5d51e2476646bde4349b050e6fcfa`。

## 使用流程

1. 更新依赖（`bun install --frozen-lockfile`），使用 Node.js 22.19 或更高版本启动 `node server.mjs`；运行机器需安装 Chrome。无需单独安装或启动 OpenFind。
2. 选择业务，进入 **主动获客 → 作品发现 → 实时搜索与自动获客**。点击对应平台登录，在 Harta 展示的官方页面中扫码；支持页面点击、拖动及检查登录状态。
3. 填写关键词，选择抖音或小红书。实时搜索按最新 / 综合 / 热门及作品形式读取作品；一键获客继续抽样作品并采集评论，结果自动进入当前业务。
4. 任务日志展示进度和异常，可以暂停或继续。已有平台作品也可直接点击「自动采集评论」或「读取完整作品」。登录失效、验证码和平台保护需要在登录页面处理后继续。
5. 展开定时采集，保存关键词和周期（15–1440 分钟）。Harta 服务运行期间持续执行，关闭页面也会同步；暂停工作流会同时停用定时采集。断开连接停止该业务的引擎和定时任务，已保存的数据保留。
6. 作品按平台、形式、日期、互动量及「近 7 天有需求表达」筛选；评论经人工核实后进入现有客户跟进。点击「参考这条创作」可带入内容生成，单次最多 3 条，快照随改写与 Excel / Markdown 导出保留。

旧 JSON 导入保留为迁移入口，日常流程不需要它。手动导入仅补全已有作品的缺失资料；实时同步会更新已实际读取的资料与互动快照。尚未读取的互动量保持「未记录」。参考作品不作为本业务事实，评论热度不等于客户意向。

## 运行与隔离

- `lib/openfind-live.mjs` 管理后台同步与调度；`lib/openfind-worker.mjs` 通过私有 IPC 调用内置引擎。浏览器无需连接额外端口。
- 每个用户、每个业务独立 SQLite、Chrome 配置及同步游标，保存在 `data/openfind/<scope hash>/`。最多同时启动 3 个业务引擎，其他业务需先断开不用的连接。
- `GET/POST /api/openfind` 使用 Harta 既有登录与同源保护；平台账号凭证、原始配置和内部服务令牌不会返回给前端。截图仅返回当前业务的官方平台页面。
- 默认后台每 4 秒检查增量；作品先同步，评论再关联，重复数据不新增证据或覆盖人工核实。无新数据不会反复创建同步任务。
- 限额、缓存、采集间隔与暂停检查点复用 OpenFind。服务重启后中断的工作流保留为暂停状态，需用户继续；不会自动越过平台保护。
- 若平台内容或登录脚本加载失败，可点「修复页面加载」切换到 OpenFind 的公网 DNS 解析与本机 CONNECT 转发；HTTPS 仍端到端加密，不忽略证书验证。仅允许平台浏览器请求的公网 HTTPS 目标，不访问本地服务。点击「恢复系统网络」可还原；有进行中的采集时先暂停。
- 可通过 `HARTA_BROWSER_EXECUTABLE` 指定浏览器，服务器可设置 `HARTA_OPENFIND_HEADLESS=1`，仍可在 Harta 查看登录截图并操作。
- 发布、私信和联系行为继续使用 Harta 原有审核流程；本接口只开放搜索和采集操作。

## 实现关联

| 能力 | Harta 关联 |
| --- | --- |
| 实时搜索与同步 | 当前业务作品库、原始链接与互动快照 |
| 评论及楼中楼 | 现有 signals、作者身份、父评论、时间、来源与核实状态 |
| 需求筛选 | 基于已读取原文的近期需求规则，未知时间不计入近期需求 |
| 客户跟进 | 人工确认后的既有联系人、购买需求与销售智能体 |
| 参考创作 | 内容生成、单篇改写、来源快照与导出 |

## 关键词、近期需求与客户跟进

- 搜索面板按当前业务城市与行业提供「求推荐／多少钱／怎么预约」关键词建议；点击建议后仍可编辑。形式选择同时作用于实时搜索和一键流程，不再被一键流程忽略。
- 平台候选判断与 Harta 作品发现、核实队列共用需求表达规则，识别选服务商、口语询价和预约路径，排除已解决、已预约、推广与作者自己的回复。宠物绝育服务不会优先采样「已绝育宠物领养」作品。平台未提供评论数时保留未知状态，不能当作零评论证明。
- 「近 7 天需求核实」按评论原始时间计算精确 168 小时窗口；缺日期、未来日期和采集时间都不能充当近期证据。核实时保留原作品、稳定评论身份、回复原文与人工依据，保存后才进入客户跟进；只确认原文、服务地点或业务适配仍不确定时，可选择「保存线索，地点或业务适配待核实」，保留待核实阶段。
- 客户跟进可直接回查需求证据、更新阶段、下一步及跟进时间，保留核实和跟进时间线；重复同步不会重复建人或覆盖已有跟进记录。阶段和下一步不代表消息已经发送。
- 抖音图文布局兼容右侧评论标签；评论分页先读取主列表，再补充未展开的回复，并滚动右侧评论容器。验证或响应异常时保留部分结果与检查点，不把无响应当作采集完成。
