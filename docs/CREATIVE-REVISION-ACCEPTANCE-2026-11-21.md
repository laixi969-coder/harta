# Harta 改稿与选型对照验收

2026-11-21。对照基线为 `9169240`。旧版内容诊断给经营者原句、理由和修改方向，经营者需要自己回到字段里改。新版把替换文字交给经营者逐条决定，并保存到同一份制作草稿。下列样稿在隔离工作区制作。

## 三份新旧稿

### 音乐教育 · 小红书图文

任务是让第一次去 Orpheus 上课的家长知道该带什么。新旧稿使用同一份学校 FAQ。校方会提供第一次课的乐器和乐谱，学过的孩子可以自行决定是否带来以前练过的谱。[学校 FAQ](https://www.orpheusacademy.com/faqs.html)

| | 发布正文 |
| --- | --- |
| 旧稿 | 第一次来试听，提前准备好学习用品。有过学习经验的孩子，出门前再检查一下。 |
| 采用后 | 第一次来试听，上课要用的琴和谱，学校会准备。有过学习经验的孩子，可以带上以前弹过的乐谱。 |

逐页稿同步改成「第一次音乐试听带什么？」「琴和谱由学校准备。」「以前弹过的乐谱，可以带来。」原稿让家长自行解释“学习用品”。新稿能从正文和图卡中分别查到校方提供的物品、学生可自选携带的物品。三项修改分别采用、逐项撤回后，原有字段逐字还原。

### 厨房收纳 · 抖音无口播短片

任务是一个人用固定机位拍出柜门为何合不上。对照采用同一组试拍条件，一部手机、一扇柜门、一只带盖盒。旧分镜取自上一轮厨房样稿的开场和跟拍段落，精简为两个镜头。验收布景设定为门沿碰到盒盖，再把盒子移开。现场是否出现相同接触点取决于实物。

| | 开场 | 揭晓 |
| --- | --- | --- |
| 旧稿 | 镜头对准杂乱的台面或打开的柜门，手部动作示意混乱。 | 镜头跟随人物在厨房走动，模拟拿取远处物品。 |
| 采用后 | 手机固定在柜外侧面，让门沿和盒盖同时入画。手轻轻合门，在接触处停一下。 | 同一机位，把盒子往里挪，再合一次门，让门沿从原来碰到的位置通过。 |

配套字幕改为「门沿碰到了哪里？」「把盒子往里挪，再合一次。」验收核对了第一镜的动作、入画位置、第二镜的变化和单人操作条件。开场、分镜和字幕三处均可独立还原。本轮没有拍摄厨房实物。[前次样稿评估](PRODUCT-OUTPUT-REVIEW-2026-11-20.md)

### 电商 · 小红书选型图文

任务是给「两款带盖玻璃盒怎么选」写一份能核对的选款稿。旧稿为「两款都能收纳，按需要选就好。」同一组商品资料进入新流程后，正文列出以下差异。

| 选型项 | IKEA 365+ 1.0 升款 | IKEA 365+ 1.8 升款 |
| --- | --- | --- |
| 连盖高度 | 7 厘米 | 12 厘米 |
| 容量 | 1.0 升 | 1.8 升 |

两款的长和宽同为 21 厘米和 15 厘米，因此成稿保留两项差异。读者可以先量层板间的可用净高，再核对需要的容量。高度使用的是连盖商品尺寸。每项差异在编辑器、下载脚本和 ZIP 中都能回查到双方的资料原文。[1.0 升款商品页](https://www.ikea.com.hk/zh/products/storing-and-washing/food-containers/ikea-365%20-spr-69269072) · [1.8 升款商品页](https://www.ikea.com.hk/zh/products/storing-and-washing/food-containers/ikea-365%2B-spr-99269075)

用两款商品页的主图各做了一张带款名标注的图卡，另有封面和选款提示，共四张 900 × 1200 PNG。验收实际生成并解压 ZIP，复核了页数、图片尺寸、商品标注、脚本及双方来源。照片仅用于本地样稿，仓库保存参数与原始商品链接。

## 按用户操作验收

| 操作 | 实测结果 |
| --- | --- |
| 在「检查与交付」运行 AI 内容诊断 | 原句与可替换的新稿同时显示。缺资料的意见可保留为建议。发起诊断时原作品和制作字段保持原值。 |
| 逆序采用同一段里的两处改稿，刷新后撤回 | 每次只改选中的那段。新加的手写旁注保留，原作品仍能单独采用制作稿。 |
| 遇到重复原句、手改原句、重叠改稿或并发保存 | 引文需要能唯一定位。已经改变的位置及过期版本会要求重新核对，有交叠的新建议不会覆盖仍可撤回的改稿。 |
| 从 5118 选择需求词 | 用已配置的官方长尾词 API 查询「收纳盒」，实际返回 30 个词。用其中的「厨房收纳盒」在手机宽度的浏览器走通选款、生成、来源回查与下载。 |
| 从导入词表选择需求词 | 实际解析 CSV，分别从「收纳盒怎么选」和「两款带盖玻璃盒怎么选」创建制作稿。词条保留来源文件与行号。 |
| 核对两款资料 | 相同数值和等价单位不自动列为差异。遇到冲突不预选，资料缺一侧不能成稿。可选择两款产品或同一产品的两种规格。 |
| 查原文、改资料后重新交付 | 展开差异可看到双方的版本、原句、行号及文件或网页。点「打开资料原文」会选中业务内的参数行。停用、过期、已撤回的来源及被改错的参数会在交付时提示。 |
| 重试与业务隔离 | 同一词条、同一平台及同一组依据重试会打开原稿。跨业务产品、伪造的引用及陈旧预览均被拒绝。 |

## 模型与验收范围

音乐与厨房的展示稿由本轮 Codex 按 Harta 的实际审稿输入编辑。三份样稿均进入 Harta 的真实保存、采用、还原或交付流程。另用基线和新版执行同一组编辑响应，音乐、厨房两例各有三条意见，旧版返回的可直接采用项均为零，新版各有三条。可重复回归使用固定的编辑响应，浏览器通过本地模型接口走完整个 HTTP 调用和写入过程。5118 查询、CSV 解析、产品原文跳转、实图排版及 ZIP 导出均已实测。

Harta 生产模型账号当天剩余保护额度为 0.03 美元，未完成三份样稿的线上供应商复测。验收没有调整生产限额。另用公开模型和公开音乐教学样稿做了补测，收到的原句有标点偏差，另一次只有补写方向。系统会要求重新定位引文或指明缺少的资料，两次输出均未计为可采用改稿。以上结果衡量的是稿件可执行性、逐处编辑和资料可追溯性。经营者盲选、实际拍摄时间及发布后的咨询量尚未采集。

本地全量检查通过了 1,181 项应用测试和 124 项 OpenFind 检查，类型检查、构建、制作页与素材交付浏览器回归均通过。

复验可运行 `npm run check` 和 `node scripts/check-creative-revision-ui.mjs`。浏览器测试默认使用隔离的 CSV 词库，另可通过 `HARTA_ACCEPTANCE_KEYWORDS` 指定已有的 5118 扩词结果文件，在同一轮核对两种来源。
