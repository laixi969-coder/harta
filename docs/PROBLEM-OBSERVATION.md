# 从真实问题到内容：实现与验收

2026-11-07。入口：内容获客 → 选题 → 从真实问题开始。既有主动获客、选题池、雷达、选题库、制作与人工发布流程全部保留。

## 范围对照

| 方案要求 | 实现 |
| --- | --- |
| 明确观察问题从哪里来 | 来源目录分别读取匿名客户问题、自有发布关联评论、公开评论、服务记录、关键词/搜索建议、对标/市场资料；答案资料独立分类。私有来信只显示数量，原始会话不会自动送模型，继续使用客户跟进的匿名提炼入口。 |
| 知道去哪里找 | 根据业务、有效产品、已有真实表达形成查找词；可保存人群/地域/场景、种子词、排除词；查找按钮复制词并进入现有作品发现。建议词明确标为假设，不冒充搜索量。 |
| 采样避免单一热门作品垄断 | 按来源类型和作品轮流抽样，近期优先。每次问题研究最多80条、每条最多1800字；记录全部可用、排除后、实际分析数量与来源ID。未取得的排序、日期、身份不推测。 |
| 观察先形成问题 | 稳定UUID、版本、处境、读者、观看理由、原文片段、来源指纹、推断、不确定事项、样本口径；同题可沿用ID或人工合并，标题可修改。 |
| 需求证据与答案依据分离 | 原话只能证明有人表达。答案仅引用已确认事实卡、有效产品来源资料、已批准销售资料或用户补充的答案资料；逐字校验引用，拒绝伪造ID和原话。人工核对不等于外部事实认证。 |
| 比较/反差/风险/判断 | 模型按可用依据选择1–3个角度，也支持过程演示；系统最多接收4个不同角度，不强行凑满。 |
| 五项检查 | 核对读者、观看理由、标题、核心答案及依据、可用收获与适用范围；不套用“15字以内”硬限制。准备创作前保存一次核对。 |
| 简单界面 | 主操作“帮我找值得讲的问题”；记录、观察范围、来源、答案核对、整理与反馈均可展开；原有入口不减少。 |
| 冷启动与失败 | 无模型时如实提供原文候选；仅有答案资料时提供探索方向；无数据不虚构高频问题。模型失败或并发更新不覆盖已有记录。 |
| 接到现有选题与制作 | 核对后按角度进入现有选题库，共用本周数量、版本控制与制作稿。快照保留问题ID、角度ID、需求证据、核心答案及答案依据。生成与独立事实核对均使用答案资料。 |
| 来源更新 | 源文、资料状态、研究用途、问题核对变化会使旧来源失效；重新整理/核对后更新选题来源并另建制作稿，历史稿不自动覆盖。生成开始和完成均检查来源。 |
| 获客筛选与内容筛选分开 | 评论可不作为客户跟进，同时显式保留研究；也可独立排除研究。历史已排除项不自动恢复，演示、作者自答、未核实摘要不恢复。派生痛点/对标/词库标为待更新。 |
| 计数与来源纠偏 | 稳定平台记录去重复抓取；不同已知用户的同一句话不合并。匿名提炼与原评论不重复计入问题目录。未知身份不推断人数。关键词命中分别记录匿名客户问题、评论、对标和业务资料；旧合计保留兼容，不当作客户人数。 |
| 发布反馈回到问题 | 同问题各角度的制作稿、真实发布版本、账号/平台、统计窗口、关联评论、咨询记录分别显示；窗口不相加，评论与咨询不相加为人数。合并问题后仍可回查原问题作品。 |
| 继续学习 | 既有发布数据与人工复盘假设进入下一次问题整理；新评论成为新的观察来源；保存下次检查日期作为页面提示，不创建外部自动化，不在后台自行付费采集。 |

## 数据与接口

- `customer.observationNotes`：人工去身份记录及答案资料，可停用/恢复。
- `customer.observationSettings`：观察范围、种子、排除词、下次检查日期。
- `customer.observedProblems`：问题、引用、角度、核对、合并与历史版本。
- `customer.observationRuns`：最近20次成功整理的范围和方法。
- `POST /api/problem-observation`：读取、记录、设置、研究用途、核对、合并、归档。
- `POST /api/problem-observation/discover`：模型整理/无模型候选；使用现有业务模型预算及高成本接口限流。
- 现有 `/api/topic-board` 与 `/api/topic-board/generate` 增加 `kind=problem`，不另建作品或发布系统。

每项操作限定当前账号和业务。修改使用版本/来源校验；模型运行期间重新读取工作区，避免覆盖其他窗口。问题整理的输出只是候选，需求存在不等于答案正确，人工核对也不等于效果验证。

## 当前执行边界

新增功能先复用已经保存的证据。外部取数继续走已有数据源连接、权限、预算和失败恢复；本功能不承诺全平台全量采集，也不以“观察计划”冒充已经执行的采集。搜索下拉不是抖音/小红书站内搜索量。私聊、通话、现场记录需要用户先去身份录入或使用既有匿名提炼；不增加后台监听。发布、发送与实际结果登记仍由用户完成。

模型能否理解引用与结论之间的逻辑关系仍需要人工核对；程序能验证来源、逐字引用、版本与隔离，不能证明所有语义结论正确。采样范围不代表全市场，平台统计仍以实际来源和口径核对。

## 验证

- `lib/problem-observation.test.mjs`：跨业务/私有来信隔离、不同用户同文与重复抓取、分层采样、独立研究资格、虚构引用/对标充当答案拒绝、核对至制作快照、源变更拦截、模型失败与并发保护、冷启动、记录/归档/合并、真实发布反馈、关键词分源、模型不能引用未送入的评论。
- `scripts/check-problem-observation-ui.mjs`：实际浏览器录入、核对修改、加入选题、生成、刷新、切业务、320–1440宽度、失败保留；使用临时业务和模拟模型。
- 现有选题库浏览器回归保持通过；完整检查包含主程序、采集模块、TypeScript与生产构建。
- 未在真实平台发送/发布内容；隔离测试不冒充真实获客成效或平台接口验收。
