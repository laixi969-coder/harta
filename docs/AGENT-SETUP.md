# 内置助手设置

用户路径：选择业务 → 创建找客户 / 内容 / 咨询接待助手 → 用内置模拟示例或自己的材料试运行 → 审阅结果后启用。

- 配置由版本化方案生成，带入业务名称、介绍、服务区域和已有线索标准。自动补齐判断规则、沟通风格、转人工条件与内容方向，不补造未知客群、价格或服务承诺。
- 提示词与工作步骤由 Harta 维护，用户无需填写 system prompt 或设计 skill。三种用途在模型试运行中使用不同的输出任务。
- 高级设置默认折叠；已有助手保持原样，可以套用推荐配置。套用保存为新版本，保留平台和账号绑定，重新试运行后启用。
- 内置示例由服务端按当前业务生成，明确标为模拟，不写入生产线索池，不发送、不发布。未配置模型时显示规则与模板结果，不称为模型生成。
- 找客户助手可用于主动获客任务；接待助手可用于客户跟进中的建议。内容助手目前生成本页试运行草稿，尚未自动贯通内容生产流水线。
- 平台连接、实际发布与发送仍由平台执行模块单独控制；启用助手不等于开放外部执行权限。

验证覆盖：默认配置不编造经营事实、用途进入模型指令、模拟样例来源、租户隔离、版本和知识变更、替换配置需重新试运行，以及桌面/手机、深浅主题与未保存编辑保护。

## 工作流质量升级

工作流版本 `2026-10-10.2`：

- 找客先区分需求、供给推广、作者回复和拒绝联系，再决定是否生成草稿；规则判断不等于购买概率。
- 内容不再采用线索评级，抖音按口播结构输出，其他平台提供标题与正文；资料不足时明确显示限制。
- 接待复用销售策略选择逻辑，区分询价、比较、购买、感谢、售后与停止营销；拒绝联系和转人工场景不调用模型起草营销话术。
- 各助手提供常规、信息不足、询价、不当要求或拒绝联系、售后五类模拟场景。结果显示处理决定、待核实项、下一步和人工复核清单。
- 生成结果执行字数、多问题、虚构动作、站外索联等规则检查，并保留既有经营事实审读。规则不能代替人工审阅。
- 工作流升级后，旧试运行不能作为新版启用依据；当前版本需要重新试运行。测试通过不代表实际业务效果达到最优，也不代表真实平台收发验收通过。

本轮验证：57 个测试文件，588 项测试通过；最后新增数值依据检查后，43 项相关测试通过；另有隔离浏览器流程验收。模拟数据与模型桩测试不作为真实模型质量或转化率证据。

真实模型验收使用虚构材料，三个助手分别生成并审读成稿，最终 3/3 通过当前检查。过程中实际修正了回复冗长、多问题合并、编造客户经历和无来源技术数字。结果只是本轮样例证据，不代表所有业务或模型输出均可靠。质量或事实审读失败时最多自动修正一次，第二次仍失败则不提供可用草稿。
