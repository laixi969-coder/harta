# 平台连接与评论获客

2026-10-10。实现状态：浏览器连接器初版，已通过隔离数据与模拟页面测试；尚未经真实登录账号验收。

## 使用路径

1. 打开 Harta「平台账号」，下载并解压连接器。Chrome 扩展程序管理页开启开发者模式，加载解压目录。
2. 在该 Chrome 个人资料中登录自己的抖音或小红书账号。不同平台账号使用不同浏览器个人资料，连接器不会替用户切换登录账号。
3. 登记账号名称，生成十分钟有效的一次性配对码。扩展弹窗填写 Harta 地址和配对码。不要分享配对码。
4. 「主动获客」添加目标账号完整主页链接，选择浏览器连接，创建读取作品任务。在扩展点击「读取待办任务」，或开启自动检查待办。
5. 进入一条作品，展开平台评论区，再创建读取评论任务。可按关键词、页面显示的 IP 属地、明确日期过滤。未知日期不会被当成最近评论。
6. 核实原文后保存线索，打开评论者主页；平台允许时私信，也可回到原作品回复对应评论。生成和复制草稿均不代表已发送，实际发送后人工登记。

## 与演示视频逐项对照

| 功能 | 当前实现 | 限制 |
| --- | --- | --- |
| 绑定自己的账号 | 新增浏览器配对、到期、撤销、设备状态 | 不是官方 OAuth，账号昵称由用户核对；登录留在 Chrome |
| 多账号 | 每个业务可登记、配对多个账号 | 不同登录账号用不同 Chrome 个人资料，无自动切号 |
| 目标账号作品 | 新增读取网页已加载的作品链接与标题 | 抖音、小红书初版；网页变化需维护适配器 |
| 读取评论 | 新增原文、作者主页、原作品、可识别 ID、时间、属地、已展开回复 | 最多 100 条，最多滚动 3 次；不保证全量，不绕过验证或隐藏内容 |
| 条件筛选 | 关键词、属地、起始日期；现有业务规则辅助核实 | 属地不是常住地；未知数据不补猜 |
| 客户线索 | 去重、作者回复排除、证据关联、人工确认 | 不将每个评论者直接视作潜客 |
| 联系评论者 | 打开主页/原作品，保留上下文，草稿、人工发送登记 | 平台是否允许私信由平台决定；无自动发送 |
| 行业智能体 | 现有配置、业务资料、产品依据、沟通建议 | 不因配对就获得平台收发权限 |
| 内容创作与发布 | 现有创作、审核、复制、发布来源登记 | 自动发布未接通 |
| 自动接待 | 现有咨询登记与回复建议 | 平台私信/评论入站同步、自动回复未接通 |
| 自动养号、自动评论引流、批量私信 | 未实现 | 不把这些演示声明当成已获得的平台能力 |

## 接口与部署

- 工作台登录后：`GET /api/browser-extension` 下载扩展；`GET /api/browser-connections`；`POST /api/browser-connections/{pair,revoke,collect,cancel,contact}`。
- 扩展端：`POST /api/connector/{pair,claim,complete}`。配对码仅可消费一次；后续使用三十天有效的独立 Bearer token；撤销立即失效。
- 服务端只保存凭证哈希于 `data/browser-connections`，不把凭证放进公共工作区。扩展令牌存在 Chrome 本地存储，不交给平台页面。
- 生产环境使用 HTTPS。扩展只在用户确认后申请对应 Harta 域名和两个平台的访问权限。
- 登录、验证码、页面不支持、失败、任务取消、浏览器未回传均有独立状态；失败不会把页面正文冒充评论。
- Harta 服务端无需也不会从此连接器获得平台 Cookie 或密码。

## 验证

`lib/platform-connector.test.mjs` 验证凭证、范围、业务隔离、取消与去重。
`scripts/check-connector-ui.mjs` 在临时工作区跑账号配对→任务→回传→核实→联系→撤销，并检查抖音、小红书模拟 DOM、登录与验证状态。
真实账号验收仍需用户安装扩展、在平台登录后实际读取，检查当前页面结构与账号权限。这一步没有完成前，不应称为生产可用的全平台连接。

## 官方授权路线

抖音评论管理需要对应授权与 scope，不能由「绑定账号」推导出可读取任意目标账号并私信所有评论者：
https://open.douyin.com/platform/resource/docs/openapi/interaction-management/comment-management-user/comment-list/

小红书开放账号的授权范围以官方公布为准：
https://openaccount.xiaohongshu.com/docs/scope

自动发布、入站同步与发送应分别获得可用接口、应用资质和账号权限后接入，并验证平台回执；不能仅打开功能按钮。

## 0.2.0 实际执行更新（2026-10-10）

本节取代上方 0.1.0 对「只读／人工发送」的描述。

已实现确认发布、评论回复、私信的浏览器执行队列与 DOM 提交适配器；增加固定关键词自动回复、指定来源的新消息读取、历史基线、每小时上限、规则暂停、发送后平台回读。

工作台「平台执行」分为发布内容、发送消息、自动回复、执行记录四项；内容获客与客户跟进直接进入相应项。浏览器需要升级 0.2.0，显式开启实际执行权限，绑定真实主页，并保持账号登录。

执行顺序：排队 → 浏览器核对身份及对象、填写 → 服务端重新核对账号、规则版本、资料及拒绝联系状态并发一次提交许可 → 浏览器点击一次 → 平台回读。准备失败可新建任务；点击后的不确定结果不能自动重试。消息成功使用 `sent_platform`，不会伪装为人工登记。发布页面仅显示成功但没有作品标识时保留 `submitted`，不声称已公开可见。

自动回复首次扫描不回复历史；之后新事件按账号、渠道和平台消息 ID 去重。仅配置的来源，自己作品需要核对作者 ID。自动回复使用用户确认的固定原文，AI 自由生成后无人审阅发送暂未开启。未匹配关键词的新咨询仍入库；人工接管、拒绝联系或频控时不自动发送。

新增接口：`GET /api/delivery`；登录态 `POST /api/delivery/{identity,asset,queue,cancel,rule}`；连接器 token `POST /api/connector/delivery-{claim,authorize,complete,asset,monitors,events}`。

新增测试：`lib/browser-delivery.test.mjs` 与 `scripts/check-delivery-ui.mjs`。隔离 DOM 验收实际执行了提交按钮并读取模拟平台新 ID，覆盖发布、私信、评论和隐私范围改变后停止；这不是生产账号发送的证明。

**真实验收待办**：用户指定使用抖音，之后再登录。当前 Chrome 抖音入口两次返回连接中断，未能进入登录页。未在任何真实平台发布测试内容或发送消息。后续使用用户另一个账号接收测试消息；发布测试仅自己可见。需继续核对真实抖音 DOM、安装／升级连接器、配对、读评论、执行发送并回读，再验证自动回复。不能以现有测试替代此验收。
