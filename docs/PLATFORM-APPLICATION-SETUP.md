# Harta 抖音、小红书扫码授权：申请与配置

更新：2026-10-10。当前尚无已审核通过的平台应用，真实扫码验收未完成。

## 用户最终看到什么

登录 Harta → 平台账号 → 选择抖音或小红书 → 对应 App 扫码并确认授权 → Harta 自动保存账号。可以只连接一个，也可以稍后连接；不强制每次登录 Harta 都重新扫码。

抖音使用官方网页展示二维码；小红书通过官方设备授权接口取得二维码链接，在 Harta 内展示。两者均不需要用户安装扩展。扫码连接仅建立官方账号授权；当前官方发布、采集、回复、私信执行通道尚未接通。原浏览器连接器保留在折叠的测试接入区，独立运行，不会因 OAuth 授权成功自动变成云端执行器。

## 由 Harta 运营方准备一次的材料

普通使用者无需申请开发者应用。由 Harta 运营方准备并在两个平台分别提交：

- 应用运营主体及平台要求的主体认证材料、联系人。
- 应用名（拟用“灵鹿线索 Harta”，以商标、名称审核为准）、图标、产品简介。
- Harta 可访问的正式 HTTPS 域名、产品演示、隐私政策和用户协议。
- 实际业务说明：用户自主连接自己的账号，管理获客内容与客户咨询；具体功能权限按平台准入范围申请。
- 官网备案及主体关系材料按各平台控制台要求准备。抖音网站应用上线文档要求官网备案主体与开发者主体一致或满足其规定的总分公司关系。[抖音网站应用上线说明](https://developer.open-douyin.com/docs/resource/zh-CN/dop/develop/app-mgmt/pub-app/)

不要把尚未接通的发布、抓取或私信能力写成已上线功能；先申请账号授权，再按实际可获批能力扩展。

## 抖音申请步骤

1. 进入[抖音开放平台](https://open.douyin.com/)，完成开发者入驻及主体认证。
2. 在控制台创建“网站应用”，填写 Harta 的应用资料、官网与所需证明。
3. 申请网页账号授权所需的 `user_info` 范围；开通情况以该应用控制台为准。
4. 配置授权回调域，与正式 Harta 域名一致。本实现的完整回调地址为：

   `https://你的Harta域名/api/platform-auth/callback/douyin`

5. 审核通过后取得 Client Key、Client Secret，存入服务端配置。测试应用允许的用户范围、上线条件按控制台提示办理。
6. 配置完成后，在 Harta 中点击“扫码连接抖音”，用自己的测试账号扫码确认；检查页面自动返回、账号记录和授权有效期。

官方扫码页、应用审核前提及授权流程见[抖音 WEB 授权接入说明](https://open.douyin.com/platform/resource/docs/develop/permission/web/permission)。本实现通过服务端交换授权码，令牌不下发给网页。

## 小红书申请步骤

1. 进入[小红书开放平台](https://openaccount.xiaohongshu.com/)的管理中心，创建 Harta 应用。
2. 提交主体、名称、图标、平台及授权范围信息；场景为 Web 扫码授权。
3. 首先申请 `basic_info`，确认应用可调用设备授权的 `device/code`、`device/token` 接口。审核、准入范围以平台实际反馈为准。
4. 取得 `app_id`、`app_secret` 并配置到 Harta 服务端。本实现使用生产环境；不要混用 Beta 环境凭证。
5. 在 Harta 中点击“扫码连接小红书”，用小红书 App 扫码，确认屏幕和手机显示的授权码一致，再确认授权。
6. Harta 按平台要求的间隔查询结果，显示“等待扫码 / 已扫码，请在手机上确认 / 已授权”。未确认、取消、超时都不保存为已连接。

申请入口与流程见[小红书快速接入](https://openaccount.xiaohongshu.com/docs/quick-start)，请求与返回字段见[官方 API 参考](https://openaccount.xiaohongshu.com/docs/api-reference)。这个设备授权流程不需要 Harta 的授权码回调地址。

## 服务端配置（开发者操作，用户不用操作）

环境变量如下，值来自平台控制台，不要发送到聊天、截图或提交到 Git：

```dotenv
HARTA_PUBLIC_ORIGIN=https://你的Harta域名
HARTA_DOUYIN_APP_ID=抖音ClientKey
HARTA_DOUYIN_APP_SECRET=抖音ClientSecret
HARTA_XHS_APP_ID=小红书app_id
HARTA_XHS_APP_SECRET=小红书app_secret
```

`HARTA_PUBLIC_ORIGIN` 只填写 HTTPS 源地址，不带路径、查询参数或结尾斜杠。只有一个平台审批通过时，只配置该平台即可。

Harta 当前不自动读取 `.env`。可以将变量交给服务管理器注入；或使用项目 Node 版本的 `node --env-file=.env server.mjs` 启动。`.env` 已在 Git 忽略清单中，文件权限设为仅运行用户可读写。当前 Mac LaunchAgent 也需要在正式配置时加入环境变量或 Node 的绝对 `.env` 文件参数，再重启服务；单独创建 `.env` 不会让现有服务自动生效。

授权记录在 `data/platform-auth/` 中以 AES-256-GCM 加密保存，目录权限 700、文件 600；密钥文件 `key` 需与数据一起妥善备份，不能放入公开静态目录。它是同机文件加密，不等同于外部 KMS；正式多实例部署需迁移到共享持久化和密钥管理服务。目前按单实例服务实现。

缺少配置时入口显示“扫码授权待开通”。配置存在只代表允许发起授权，是否获批及凭证是否有效仍由真实平台响应确认。

## 授权与业务权限分别验收

| 能力 | 扫码后是否自动获得 | 后续处理 |
| --- | --- | --- |
| 应用范围内的账号身份 | 取决于基础授权成功 | 已实现令牌交换和账号保存；真实验收待申请 |
| 发布内容 | 否 | 核实平台发布 API、账号类型、素材和权限要求，再实现与验收 |
| 自己作品的评论读取 / 回复 | 否 | 分别确认接口权限、数据范围、分页与回复条件 |
| 任意目标账号的评论采集 | 否 | 不能把自己作品接口当成第三方评论全量采集接口 |
| 私信 | 否 | 核实企业身份、会话及收件人限制；不能承诺可任意私信陌生人 |

小红书快速接入页说明基础授权范围；其权限页的扩展能力仍需与平台确认实际开放情况，不能将规划条目作为已可调用接口。[小红书权限说明](https://openaccount.xiaohongshu.com/docs/scope)

抖音评论管理与企业消息有独立说明，申请基础登录后仍需逐项申请和联调：[评论管理方案](https://open.douyin.com/platform/resource/docs/ability/interaction-management/video-comment-management-solution)、[企业消息接口](https://open.douyin.com/platform/resource/docs/openapi/enterprise-open-ability/message-management-enterprise/message-to-user/)。

## 上线验收与未完成项

1. 真实扫码成功后，返回正确 Harta 用户与业务，刷新仍保留账号；另一个 Harta 用户看不到该授权。
2. 取消、拒绝、过期、不匹配的回调与重复授权码不会建立错误连接。
3. 同一账号重新授权更新原记录；应用范围的 open_id 不冒充网页主页 ID。
4. 逐项验证业务接口后再开放对应能力；测试发布仍按用户要求仅自己可见，测试消息只发往用户控制的另一个账号。
5. 当前“从 Harta 断开”删除本地令牌，不宣称已经撤销平台侧授权；用户可在平台 App 的授权管理中撤销。
6. 当前授权到期提示重新连接。自动刷新令牌、平台主动撤销通知、服务器端主动撤销接口、真实用户昵称读取及官方业务 API 是后续工作；不能承诺永久免登录。
7. 本文描述官方授权路径。另行实现的内置浏览器路径与真实验收进度见 [内置浏览器验收记录](HOSTED-BROWSER-ACCEPTANCE.md)。

已验证：隔离环境中的协议响应、会话绑定、一次性 state、服务端密文存储、取消后的迟到响应、二维码地址检查、配置缺失、界面状态和现有连接器回归。上述测试不代表真实平台账号联调通过。
