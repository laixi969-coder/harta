# Harta：按用户任务重新组织获客流程

## 原问题

首页把找客、创作、产品和报告并排展示。内容工作区沿用了客户诊断阶段；找客入口又进入另一套双路径首页。用户必须先理解产品、业务、联系人、购买需求和智能体的内部划分，才能判断第一步。空产品目录同时显示“添加另一款产品”，价格等低频字段占据首屏。

## 新主流程

建立业务（名称、介绍） → 选择获客路径 → 完成行动 → 客户跟进。

- 内容获客：选择推广内容与结果目标 → 生成、修改 → 到平台发布 → 登记真实咨询。
- 主动获客：查找公开需求或导入已有资料 → 核实来源 → 保存客户 → 联系、跟进。
- 两条路径共用业务资料、产品与联系人；业务准备不再作为默认第一屏。

## 已实现

1. 主导航按工作台、内容获客、主动获客、客户跟进排序。产品、资料、智能体和设置分入业务准备，报告保留在次级入口。右上角统一为添加业务。
2. 空账号直接显示最小建档表单。业务创建后回到路径选择，无需先建立产品、规格或智能体。
3. 首页突出一个建议动作：待回复优先，其后为到期需求、资料变更核对、待核实需求，最后是继续/开始内容。按当前业务隔离，禁止联系、已结束购买需求不进入到期提醒。
4. 内容获客有独立任务入口，已有批次可直达成品。内容模式只展示内容批次，不把诊断报告当成内容；不修改客户原有阶段。编辑页默认显示成品，新批次创作按需展开。选择目标后保存再生成，失败保留输入。
5. 主动获客明确需求来源与步骤。搜索与导入页面不再重复双路径首页；发布登记有单独标题及返回所属路径的入口。
6. 客户跟进说明两条来源的汇合关系。未建立购买需求的联系人可以直接查看咨询并回复；复购或多产品需求仍可独立建档。
7. 产品空状态只保留一个录入区。名称、事实、来源为首要字段；价格、有效期、推广状态及销售知识库按需展开。保存后提供两条获客路径入口。保留编辑草稿与补充区域展开状态。
8. 业务选择在新工作台、原有需求/发布记录与内容编辑之间传递，切换业务不串用未保存表单。
9. 中文任务标签替代内容工作区的大英文功能块；保持深浅主题、键盘焦点和小屏布局。离开报告页时收起历史导航，避免手机首屏被历史入口占满。

## 验证

- `npm test -- --reporter=dot`：51 个文件、523 项测试通过。另修正旧测试误将随机哈希中的 `888` 当作其他产品报价的偶发误报，改为检查价格文本及知识所属产品。
- `scripts/check-commerce-ui.mjs`：产品/规格、资料、跨业务草稿、评论与回复层级、独立购买需求、沟通草稿与人工发送记录、内容范围，以及 320/375/414/768px、深浅主题与文字对比度。
- `scripts/check-journey-ui.mjs`：空账号建档、无产品直接创作、生成失败后的输入保留和目标保存、主动导入、添加第二业务及上下文隔离。生成失败用明确的本地拦截模拟，不发起付费生成请求。
- `scripts/check-acquisition-ui.mjs`：保留原有发布、咨询、核实、历史会话、智能体与任务详情验收，入口更新到新的任务路径。

浏览器验收使用临时工作区和合成资料，不改动真实客户数据。截图位于 `output/journey-review/`。生成内容质量沿用原有测试，本轮未执行线上平台发布或自动联系。

## 能力边界

本轮调整信息结构、流程衔接、界面主次和上下文传递。公开搜索仍取决于数据源配置；平台评论自动读取、内容自动发布、消息自动同步和发送仍未接通。界面只把已经存在的能力接成流程，不将人工记录展示成平台自动执行。
