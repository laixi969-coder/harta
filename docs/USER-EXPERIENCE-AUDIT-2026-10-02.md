# Harta 用户流程与对抗式审查

日期：2026-10-02。范围：当前 main 上的内容升级、账号入口、设置、缓存、后台任务和请求防护。

## 先复述计划

让第一次使用 Harta 的人，只需提供自己的业务资料、选择想获得的结果，就能低成本拿到可使用的内容。系统负责研究、组织、校验和纠错；用户不需要理解模型、缓存、提示词、方法论。目标是相关流量、传播、有效客资或成交，不能用生成篇数或模型评分替代。通过实际用户走查和对抗式检查发现阻碍、修复并回归；强化缓存及请求防护，最后提交并推送 main。

结论：先做最小实验，再逐项修复，不推倒重来。本轮已完成确定性安全、状态和缓存反例验证；增长结果需要真实发布数据，不能据此宣称流量或销售已提升。

## 应简化、修正、隐藏的东西

- 主路径：提供业务资料 → 选择“更多人看到 / 转发 / 咨询 / 下单” → “帮我写六篇” → 查看成品、复制或“帮我改一下”。默认咨询目标即可开始。
- 收起选填内容：偏好、事实确认、研究来源、效果记录、批次导入导出。保留在更多设置或更多选项，不能挡住生成与使用成品。
- 不向普通用户展示：模型路由、缓存键、质量检查规则、并发预算、提示词原理。管理员的连接设置继续仅对管理员开放。
- 必须展示：正在处理、保存失败及重试方式、资料改变导致候选过期、缺少业务依据、当前稿件是否已发布。这些直接影响用户决定，不能为了简洁隐藏。
- 首次账号只增加必要的激活码。管理员私下发给本人，避免知道邮箱的人抢先注册；已正常设置密码的用户继续正常登录。

## 真实浏览器走查记录与限制

本次用户消息中的网址为模板占位符 `[网址]`，没有提供生产网址。使用本地隔离实例 `http://127.0.0.1:50561/`，隔离账号与客户数据，不对真实客户执行测试注册或压测。

1. 启动隔离实例；命令行 HTTP 请求可收到登录跳转和正常响应。
2. 在 Codex 内置浏览器实际打开本地地址，返回 `ERR_BLOCKED_BY_CLIENT`。
3. 在 Chrome 实际打开同一测试登录页，同样返回 `ERR_BLOCKED_BY_CLIENT`。
4. 用电脑控制功能选中 Chrome 的测试标签，亲眼确认页面显示“127.0.0.1 已被屏蔽 / 此页面已被 Chrome 屏蔽”。保存截图 `output/playwright/audit-browser-blocked.png`。
5. 没有关闭浏览器安全保护、安装绕过工具或把接口测试冒充页面点击。

**因此本轮注册、修改设置及完整二次走查未完成，页面加载速度、按钮可发现性和浏览器返回后的表现也未能重新确认。** 下面的代码/API发现均单独标明证据，不能当作已观察到的浏览器行为。此前轮次已有成品复制与目标切换截图，但它们不证明本轮安全改动后的 UI 回归通过。

当前项目代码没有结账、订单支付入口；这不是实际浏览器确认的结论，也没有执行任何支付。若用户所指的另一个部署包含结账，需要准确网址和对应测试环境才能覆盖该流程。

## 按严重程度排序的问题

以下在服务测试或代码追踪中确认；不是虚构的浏览器观察。最终测试命令和计数见文末。

### P1：仅凭白名单邮箱可以抢先注册或接管已重设账号

- 复现：管理员将邮箱加入名单或重设该账号；攻击者知道邮箱后提交新密码。旧流程无激活凭证。
- 根因：名单代表“允许注册”，却被同时当成“证明本人身份”；首次管理员也可被任意首次密码初始化。
- 修复：24 小时、一次性激活码，只保存哈希；管理员开通/重发/重设时显示原码；注册验证邮箱与激活码。首次管理员验证部署预设密码。已有正常密码保持兼容。撤销名单、重设、改密处理旧会话。
- 验证：账号单元测试与真实 HTTP 安全回归覆盖无代码、错误代码、过期、复用和旧会话拒绝。

### P1：业务资料变化后恢复历史稿可重新带出旧承诺

- 复现：保存一个版本，修改服务范围/价格/事实后，恢复之前的历史版本。
- 根因：候选采用校验业务版本，恢复历史分支缺少同等校验。
- 修复：历史版本保存业务资料基准，恢复前校验；过时或缺少基准的历史仅供查看，需按当前资料重新改写。
- 验证：业务变更后恢复拒绝，原文不被覆盖；资料一致时允许恢复。

### P1：请求和后台生成缺少完整资源上限

- 复现：从多个客户连续启动后台生成；同时调用等待模型或读取资料的耗时接口。
- 根因：HTTP 请求很快返回并不代表后台任务完成，仅限制请求频次无法控制实际模型工作量；旧 IP 计数条目缺少容量治理。
- 修复：按账号与全局限制实际任务数量，忙碌时可重试；对耗时接口统一容量控制；限流表和会话容量有上限，超时释放，避免无限增长。
- 验证：受控并发和资源释放测试。未向生产站点发送攻击流量。

### P1：跨站变更、异常输入与静态路径防护不足

- 复现：带不同 Origin 的变更请求，畸形 Cookie、null/数组 JSON、超过限制的请求体，以及尝试读取非公开服务器文件。
- 根因：请求入口未统一验证来源/形状/体积，静态文件防护仅靠路径与扩展名不足以覆盖真实路径逃逸。
- 修复：同源变更校验、明确 400/413、公开资源白名单与真实路径约束、响应安全头、连接及请求超时。
- 验证：安全 HTTP 测试验证拒绝与正常请求兼容。防爬不使用容易伪造的 User-Agent 当作安全边界。

### P2：改模型或研究配置后可能复用旧研究

- 复现：业务资料不变，切换模型或数据源后再请求研究；另构造过多词库缓存项。
- 根因：缓存身份未完整包含生成依赖，词库缓存缺少容量边界。
- 修复：缓存身份加入必要配置依赖，缺少身份的旧缓存不复用；缓存限制容量与有效期，失败不伪装成有效缓存。
- 验证：配置变更失效、TTL、容量及现有命中路径测试。

### P2：编辑已发布文案后仍显示“已发布”

- 复现：将某篇标为已发布，再编辑该篇正文。
- 根因：手工编辑入口更新稿件，未同步该篇发布状态。
- 修复：正文变化只重置受影响的篇目到待发布，保留旧效果快照，不误称新稿已经发布。
- 验证：发布→编辑状态回归及不影响其他篇目测试。

### P2：异步重绘可能丢失未提交的效果记录或改写要求

- 复现：编辑某篇效果表单或改写输入，同时另一操作成功触发内容列表重绘。
- 根因：输入只存在于即将替换的 DOM 中。
- 修复：按客户、批次、篇目保留草稿，渲染恢复；提交成功只清除已提交且未继续编辑的那份草稿。
- 验证：草稿隔离与渲染恢复回归；本轮真实浏览器复测仍受阻。

### P2：账号设置请求失败缺少可恢复状态

- 复现方法：更改密码或开通账号时使请求失败（本轮静态代码追踪，浏览器故障注入未完成）。
- 根因：事件回调缺少异常处理和提交中锁定，失败时无法给用户明确反馈。
- 修复：提交中禁用重复操作，失败提示并保留输入；成功只清除本次提交内容，避免清掉等待期间继续输入的新值。
- 验证：语法和变更审阅通过，浏览器断网重试仍待补验。

## 上线与验收边界

应用层限流降低单机资源滥用，不能抵挡超过服务器带宽的 DDoS。边缘 CDN/WAF、源站仅允许代理访问、可信代理与 HTTPS 配置仍需在真实部署上配置并验证；本轮不会声称已替用户购买或配置外部服务。

浏览器走查受阻属于外部验证限制，不计作修复失败。按要求提交并推送代码，不等于宣布所有体验流程已验收。完整页面回归仍需在浏览器可访问的地址继续。

## 复查追加发现

- P2：自动修复恰好返回原句时，旧手工覆盖仍留在文案上。现会删除旧覆盖，实际改动同步更新发布状态；无改动不重置。
- P2：目标保存期间切换客户，异步回调可能把 A 的目标显示成 B 的设置。现按当前客户重新渲染，并按客户隔离未保存补充要求；已有模拟事件回归。
- P2：历史研究取第一条匹配而非最新记录，浅拷贝还可能污染历史嵌套对象。现选最近有效快照并深拷贝，过期和未来时间不命中。
- P2：过长事实适用范围、效果备注原来会变为空串。现明确拒绝并提示缩短，不悄悄丢掉条件。
- P1：后台任务报错后，如果连失败状态都写不进磁盘，后台 Promise 拒绝可能未被处理。现保留固定错误日志、可靠释放任务名额，并由已有失效任务机制处理恢复状态；有不可写磁盘反例测试。

页面草稿保护目前覆盖当前页面内的客户/批次切换及异步重绘；不保证刷新、关闭或重新登录恢复未保存内容，不将其描述为持久自动保存。

两个耗时操作池分别为每账号 2、全局 8：后台生成与同步耗时接口彼此独立，单进程合计最多 16 个已接纳操作，内部可能调用多个上游接口。多进程需共享配额。部署变量、HTTPS、代理可信来源与边缘配置见 [服务保护与部署说明](../deploy/native/SECURITY.md)。
