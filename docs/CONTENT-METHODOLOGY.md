# Harta 内容方法 v2

方法服务于选题、写作、制作和复盘：**处境 → 切口 → 兑现 → 承接 → 验证**。它是可调整的编辑方法，不是固定脚本，也不是流量预测模型。

1. **处境**：明确读者处于什么场景、要做什么决定、具体卡在哪里。优先使用业务资料和真实评论；未核实的需求标为假设。
2. **切口**：围绕一个有价值的问题，从对照、误区、代价、过程细节等方向选择表达。标题、封面和开头指向同一承诺，不靠虚假冲突换点击。
3. **兑现**：尽早给出可使用的判断、步骤或观察，并说明证据与适用边界。图文逐页推进，视频画面配合口播，长文分层回答；信息流首屏应接住广告承诺。
4. **承接**：传播目标先提供独立价值；获客目标说明适合的人和有依据的服务边界；成交目标回应真实购买疑虑。下一步须符合渠道与实际能力，不能编造价格、优惠、案例或预约方式。
5. **验证**：按平台、形式、账号和统计窗口记录播放、互动、咨询、去重后的有效线索或订单等对应指标。与可比基线比较，下一次优先改变一个关键因素；样本不足或口径不一致时保留为假设，不把相关性写成因果。

举例：同样是厨房收纳，传播内容可以回答“为什么收纳盒买回家放不进去”，给出可自行执行的测量步骤；获客内容可以围绕适合咨询的具体问题，使用已确认的服务范围和联系方法。资料没有提供具体尺寸标准时，不写确定数值或最优承诺。

方法已用于创意候选、独立筛选、成稿、单篇改写与制作建议。内容创作页面可查看概述；作品制作的「检查与交付 → AI 内容诊断」按当前草稿、目标及业务资料提出最多三条建议，逐条引用草稿原文，不自动改稿。诊断建议不得新增资料和草稿中没有的阿拉伯数字，但这不是事实验证；请继续使用事实核对并人工审阅。草稿或业务资料变化后，需要重新诊断。

记录真实结果前，不可宣称这套方法已带来高流量或高转化。历史稿没有版本标记不代表经过本方法创作；经候选筛选后生成的内容批次会记录方法版本作为创作背景，而不是效果认证。单篇制作使用当前方法，不自动补写历史批次版本。


## 分入口与形式的编辑侧重

- **信息流**：自然推荐先让陌生读者看懂并获得价值；付费素材保持首屏承诺、正文和真实承接一致，兼用时分别观察实际来源。信息流与平台、图文 / 视频是独立维度。
- **小红书图文**：标题补充场景，封面聚焦一个问题，逐页推进判断或动作；视频用可拍的过程或对照兑现标题与封面。
- **抖音图文**：封面交代问题，逐页形成前后关系；视频在首个镜头及第一句话呈现具体问题或动作，让画面、口播与收口一致。
- **流量与传播**：先交付可独立使用的价值，非必要不默认私信；**线索与成交**：明确适合谁、可信依据和可兑现的下一步。具体任务优先于批次总目标，双目标的播放与有效线索分别记录。

这些是编辑假设而非平台算法或效果承诺。制作建议会对部分资料中不存在的“免费 / 免单 / 百分比”等触发一次修订尝试；失败时原文保留并明确提示，规则并不覆盖所有失实说法。生成后还会另行调用模型核对事实；核对结论及生成时提示随制作稿保存，历史提示需要结合当前内容重新确认，核对不可用不会显示为通过。AI 内容诊断引用当前草稿，不自动改稿。

## 真实模型测试记录

2026-10-31 使用独立合成业务运行 16 组矩阵：小红书 / 抖音各自的图文与视频，流量与获客目标；信息流在抖音承载下另分自然和付费。第一轮完成 14 组生成，其中 13 组完成事实辅助核对、11 组完成内容诊断；后续调用触及正常模型费用 / 请求额度，最后 2 组无法生成，1 组生成后的两项审读未完成。事实辅助核对在 5 组提出待核实问题；这些是模型意见，不等于人工验证的错误率。

第一轮还发现，8 组图文中有 6 组输出不能直接按当前逐页出图规则使用；现已针对明确分组、连续编号的画面 / 文字，以及不改变原文的换行重排添加处理和自动化测试。不明确时保留原文并提示手工整理。上述修复是在真实模型额度用完后完成的，**尚未以真实模型复测**；不可将单元测试视为实测修复率。

合成测试明细保存在本机 `output/content-quality/matrix-live.json`。额度恢复后可运行 `node scripts/check-content-matrix-live.mjs` 重跑全部，或追加场景编号运行指定场景；它会使用正常模型额度，创建并清理独立合成工作空间，不读取用户业务内容。该脚本现使用实际的生成后事实核对流程，并检查图文是否满足逐页格式。
