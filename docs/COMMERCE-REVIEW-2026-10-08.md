# 多产品、评论找客与沟通工作台：实现和审查记录

用户已授权从原型进入正式调整，并要求修复缺陷、做对抗审查、直接提交和推送 main。本记录优先于旧文档中的“仅原型”“保持旧视觉”以及 v0.3 未覆盖清单；未在本记录声明完成的目标仍按待开发处理。

## 已实现的使用路径

- 今天：选择业务，查看该业务已保存记录中的待核对内容、待核实评论和待回复联系人；可以直接继续内容、找客户、整理产品或添加业务。
- 产品与服务：创建和编辑多个产品、可选规格；事实、参数和价格必须有来源，保存带版本校验。业务间隔离未保存的表单，SKU 不拆成独立业务。
- 内容：保留原有编辑器、研究、事实资料、关键词、历史批次和诊断；新增品牌／单产品／多产品范围。选规格会带入产品，取消产品会移除其规格。单篇改写沿用本批产品范围；采用候选和恢复历史版本也校验事实版本。
- 找客户：登记其他账号及其视频，导入有原文和链接的真实评论，按父评论显示楼中楼。识别已登记的作者 ID，作者回复不作为新客户；核实评论后建立联系人，可直接进入购买需求与沟通。
- 客户与咨询：同一联系人可同时有“已成交的旧需求”和“比较中的新需求”，分别保存阶段、产品、规格、证据和下一步。咨询、人工回复和智能体草稿按购买需求归属；未关联需求的旧会话仍保留入口。
- 智能体：保留业务角色配置、版本、知识快照、账号绑定、试运行、启停与历史。已启用接待职责的角色可结合指定原评论、视频语境、当前会话和选定产品起草；未配置模型时明确标为澄清模板。任务保存版本、范围、账号、接收对象及运行状态。
- 发送：复制和实际发送是两个动作。人工登记实际发送必须确认、填写时间和依据，不自动改变购买阶段。拒绝联系、人工接管或结束的购买需求会阻止智能体继续起草。

主导航为今天、产品与服务、内容、找客户、客户与咨询、业务资料、智能体、设置；旧诊断报告、跟进与复盘、发布与来源、历史会话、全组放在可展开的报告与记录中。页面不出现甲方／乙方、自营／代客的身份分类。视觉采用中性浅色／深色双主题与橙色强调，状态通过文字呈现。

## 第一性原理与对抗审查

审查按下面的不变量追踪服务端入口、异步落盘及浏览器操作，再构造反例。发现的问题均修复并加入对应回归验证。

| 不变量 | 对抗输入或操作 | 修复及验证 |
| --- | --- | --- |
| 所有对象属于当前用户和业务 | 伪造其他成员的业务、账号、产品或角色 ID | 服务端校验归属；真实 HTTP 与业务模块测试拒绝越权 |
| 产品选择在完整内容链中成立 | 点击某产品写内容，随后单篇改写；在候选生成后修改产品 | 修复预选被表单缓存覆盖；生成和改写采用所选事实，候选和恢复版本重新校验 |
| 同一人可以有不同购买进展 | 为同一联系人建立比较中与已成交需求；登记发送 | 阶段互不覆盖；发送不改变本次购买阶段 |
| 新建需求可以没有产品 | 联系人建立后打开新增需求，传入空产品对象 | 修复空值造成的浏览器异常；真实浏览器完整流程覆盖 |
| 评论身份和回复关系不可冲突 | 同一批使用相同评论 ID 指向不同视频；构造循环父评论 | 整批校验后写入；冲突和循环拒绝，不能部分保存 |
| 原文是数据而不是可执行内容 | 评论昵称和文本含 HTML/script | 浏览器转义渲染，没有注入图像或脚本执行 |
| 消息去重不能掩盖串单 | 同一平台消息 ID 重新绑定另一需求或不同原文 | 拒绝冲突；相同账号、渠道、需求和原文的重复输入保持幂等 |
| 消息的实际先后不是导入先后 | 较旧的消息较晚导入；登记早于新咨询的发送 | 按事件时间选最新咨询；早于咨询的发送不清除待回复状态 |
| 草稿必须基于当前控制状态 | 生成时人工接管；复制前暂停角色、更新产品或拒绝联系 | 丢弃迟到输出，失效草稿不能复制；旧人工接管可凭依据恢复，不能借此解除拒绝联系 |
| 无法确认的外部动作不计成功 | 伪造浏览器能力标志要求自动沟通 | 服务端拒绝自动／确认发送模式；复制不计发送，无真实平台回执 |
| 慢模型和错误不损坏状态 | 模型超时后迟到返回；错误消息包含账号关键字及秘密片段 | 90 秒可见超时，不保存迟到草稿；真实 provider 未结束前保留并发占位；公开运行错误仅用允许文案，旧建议接口也屏蔽模型和核对服务错误原文 |
| 更新不改写历史 | 改产品资料后检查旧内容、发布版本与恢复候选 | 内容标待核对；旧快照保留；重新核对要求当前内容和资料的哈希一致 |

任务运行在现有服务端和用户工作区中，未新增外部发送。工作区继续使用旧 Customer ID，新增对象存入 acquisition；旧内容未关联产品时不猜测或强制回填。

## 明确的能力边界

1. **抖音、小红书等平台的站内实时评论读取、自动消息接收及发送未接通。** 当前真实可用的是资料导入、公开搜索摘要（需已有搜索配置）、上下文草稿和人工登记。连接器、调度、授权、幂等发送、回执及失败恢复仍需开发和真实账号验收，不能只靠补一个账号启用。
2. 目标视频以真实链接、标题和用户提供语境呈现；没有伪造封面、播放或抓取成功。JSON 导入有最多 100 条限制；尚未支持平台游标和自动增量读取。
3. 产品引用按本批选择及产品／规格版本保存，变更按版本保守提示核对；尚未做到句子和字段级的精确依赖分析。已发布版本保留历史，不自动更正平台内容。人工登记过去实际发送／发布的版本仍允许保存真实历史依据，不等于重新批准旧版本继续发送。
4. 产品批量表格导入、自动产品关联、自动创建购买需求、跨业务聚合首页、按产品精确归因、成交订单及库存均未实现。当前成交阶段是人工记录，不代表已核验订单或营收。
5. 自动对话不存在后台持续营销行为；接待角色目前只按明确操作生成建议。模型辅助事实核对也不是独立事实认证，用户仍需审阅草稿。没有配置模型时仅验证了规则／模板路径，模型异常和异步边界由注入测试覆盖。
6. 现有 JSON 工作区采用单服务进程的同步读写，异步生成完成时重新读取并检查上下文。多副本生产部署仍需数据库事务和跨进程任务协调。
