# Harta 内容质量升级：从用户要完成的事倒推

## 2026-10-08 · 先筛选创意，再交付精选内容

本节描述最新流程；下文的固定六篇是此前版本的实现记录。

### 已落地

- 研究后先调用独立的创意规划阶段，从业务补充、卖点、当前取样附件、已确认事实中摘录可用素材。每项摘录保存来源与连续原文，程序核验原文确实存在；待确认和停用事实不会作为已确认事实卡来源。资料矛盾仍交由模型对照，不能把原文存在当成真实性认证。
- 生成 6–10 个简短候选，描述目标读者、问题、切口、形式、读者收益、开头、行动理由、证据和制作办法。没有独有素材时可用有边界的一般建议；不要求用户先补资料，也不把资料缺项当成卖点。
- 再调用独立筛选阶段，选出并排序 1–3 项，剩余候选逐项记录淘汰理由。验证候选编号、来源和筛选覆盖情况，拒绝凭空增加、重复或漏掉候选。允许清单与演示等组合形式，不用固定格式枚举限制创意。
- 写作只接收入选项，并严格按入选编号和顺序交付。标题、封面、开头、正文围绕同一收益；资料对照审读同时检查是否兑现入选创意的具体问题和收益。结构、去重、硬风险和业务事实核对保留；失败不偷偷退回旧的六篇生成路径。
- 默认按钮改为“帮我挑选并写好”，显示实际篇数和真实任务阶段。每篇展示一句推荐理由；手工编辑后隐藏旧推荐，模型单篇改写后使用更新后的理由。创意筛选快照及一个可选素材建议折叠展示，不增加必填步骤。
- 每批保存 `creationPlan`：素材摘录、候选、入选/淘汰理由、选填素材建议、生成时间和判断边界。历史备份的 Excel / Markdown 保留该快照；普通选中内容导出仍只包含选中篇目的成品与创作依据。旧六篇批次保持原样可读、可改写。
- 清单、编号、小标题、没有第一人称，以及商家作为句子主语，不再作为质量硬错误。具体事实仍要经过资料核对，口号、重复、标题上限与现有风险检查仍生效。兼容生成与自动修复提示词同步移除相反要求。
- 标题长度、重复等交付问题与事实问题在同一轮反馈，避免先修格式耗尽事实修订机会。审读明确区分一般性核对建议与经营承诺；若错误列表要求“保留原文”，会重审同一原稿一次，持续矛盾则失败，不静默忽略。成稿审读只检查当前 items；传入的选题目标不再携带旧候选标题或开头，避免已舍弃表达污染检查。
- 研究正文读取预算从前两项改为最多四项，优先覆盖不同查询，防止第一条查询占满预算。读取失败保留摘要标记；异步完成不改变来源编号。更新研究缓存版本。

- 新增候选引用、长资料取样、唯一编号、筛选覆盖、顺序锁定、单篇入选、失败路径、旧六篇改写和界面转义等回归验证。全流程测试使用真实生成编排与检查器，模型回复由测试夹具提供。
- 首次真实模型试跑在候选阶段失败，暴露组合内容形式被过窄枚举拒绝、缺项提示不够具体的问题。诊断样本还出现业务来源编号误填到外部研究来源字段。已允许组合形式，逐项指出缺失字段，并在带完整草稿的重试中明确区分业务素材与外部研究编号；没有放宽引用真实性检查。
- 后续试跑暴露模型把已支持事实或一般问题当成经营承诺、将“保留”列为错误，以及形式说明过长造成的无意义拦截。已校准审读边界，增加矛盾重审，取消形式说明的硬长度限制。筛选返回的 `id` 可规范化为 `candidateId`，两者冲突仍拒绝。成稿缺省的空引用列表规范化为 `[]`，不补造证据，非空错误引用仍拒绝。后续真实回复的 gate 返回结构化对象，现保留原信息转换为展示文字，模型标为 verifiedFacts 的部分明确注明非独立认证；空对象仍退回，正文仍须核对。成稿漏写制作建议时，重试会逐篇指出准确字段位置，避免泛泛报错后原样重发。审读引文若带有候选编号和字段路径，必须在该候选的指定字段逐段匹配后才能恢复修改意见，防止定位失败耗尽写作重试；编号、字段或引文不符仍拒绝。

## 首先定义“更好的输出”

用户真正要完成的是：用自己的业务资料，以可承受的成本，做出更能带来目标人群流量、爆款传播、有效客资或卖货成交的内容。可信、可制作、少修改是基础要求；让合适的人理解价值是过程；增长结果才是目标。生成篇数、文案长度、采用率和模型自评分都不能单独证明目标完成。

从第一性原理倒推，读者需要先有理由停下来，再有理由继续看，最后按本篇目的产生分享、咨询或购买等行为。不同目标的关键阻碍不同，因此应先确定用户要什么结果，再设计内容，而不能给所有业务套同一种文案结构。

| 主要目标 | 内容需要解决的问题 | 发布后的主要判断依据 |
| --- | --- | --- |
| 目标流量 | 相关人群为什么点开、为什么继续看？ | 实际曝光、阅读或播放，结合受众与业务的相关性；停留等可得数据用于诊断 |
| 爆款传播 | 读者为什么愿意把内容转给别人？ | 实际分享，以及相对同账号或可比内容基线的表现；预先约定统计窗口 |
| 有效客资 | 有需要、符合服务条件的人为什么相信并主动联系？ | 符合事先定义条件的去重客资；咨询次数作为辅助记录 |
| 卖货成交 | 有需求的人还缺什么信息或信任才能购买？ | 可核实、可归因的订单与收入，并考虑退款和制作成本 |

这些是待验证的内容策略，不是平台算法定律。爆款只能在发布后按约定基线识别；发布前只能提出潜力假设。不能为了点击编造冲突、案例、稀缺性或经营承诺。

因此，Harta 应围绕“本批要争取什么结果、每篇承担什么作用、如何验证”组织工作。保留当前一个主平台、六篇内容的节奏，但不机械规定六篇都引导咨询，也不要求每篇同时有流量、有客资、有成交。低播放但带来适合客户的内容，可能达成获客目标；高播放但没有目标客户的内容，不能据此宣布获客成功。

## 本轮已落实

| 用户痛点 | 实现变化 | 验收方式 |
| --- | --- | --- |
| 明明写了业务限制，生成却忽略 | 研究与写作共享业务上下文，保存的业务补充完整进入提示词；附件使用独立预算，超预算按段保留头尾并明示取样 | 12,000 字补充末尾限制及附件内容都出现在两阶段提示词中 |
| 内容像行业通稿，不像自己的业务 | 写作阶段明确传入客户名称、行业、城市、卖点；调用方未传 material 时保留已有 sourceMaterial | 无外部研究时仍能看到业务基本信息 |
| 看不懂为什么出这六篇 | 每篇保存目标读者、具体问题、读者收益、依据与边界、自然下一步；每篇内容卡可展开查看，批次 Excel/Markdown 导出同步保留 | 缺关键字段或引用不存在的研究编号会退回；按选中范围导出依据 |
| 改过的文章又生成一遍 | 合并报告与内容批次后按时间取最近三份，读取最终编辑版；忽略标点、空白和全半角差异进行重复检查 | 历史改稿、跨批次排序、批内重复回归测试 |
| 生成结束才发现有硬问题，还得手动再点 | 交付验收覆盖平台字段、重复、现有质量与红线检查；失败时带完整草稿和具体问题最多自动改写两次 | 真实检查器参与测试；持续失败明确返回错误，不伪装成完成 |
| 格式正确，却编出免费服务或工期承诺 | 增加独立于写作的资料对照步骤，用原始业务资料和实际来源核对价格、数字、经营经历、服务承诺及行动一致性；模型策略不作为经营事实依据 | 无依据承诺进入修订；审读异常、结论矛盾或无法定位原文时不视为通过 |
| 只改一句，正文和其他版本对不上 | 新自然内容流程按整篇返回修订，复检全部字段；保留字段改动记录；基础文案兼容层读取可见平台正文 | 原文与平台正文一致；修改平台正文后旧隐藏稿不再报残留错误 |
| 文章漏正文、分镜返回数组导致崩溃 | 公众号、知乎、朋友圈纳入共享交付字段；异常字段类型报告缺件并可重试 | 缺正文及非字符串分镜测试 |

创作依据只代表生成时的计划与理由。用户编辑成品后，依据说明不会自动改写；界面与导出均提示需一并核对。现有历史档无需补造这些字段。

## 能力边界与需要真实数据的部分

- 效果为用户填写或导入的数据，不是平台核验结果。有效客资的去重和订单归因由用户提供口径，系统不把咨询次数换算成客资人数；重叠窗口不累加。
- 未连接平台自动发布、流量回传、电商交易或 CRM 的身份去重。这些需要确定具体平台、官方接口权益及账号授权；当前手工与导入路径可用，不阻塞内容生成。
- 事实卡的自动提取验证的是“原文存在”，用户确认不是独立事实认证。冲突的说法可以并列核对，但没有确定性的语义冲突检测器；模型被要求不要自行选取冲突承诺，仍需用户核对。
- 单篇改写会更新创作依据；直接手工编辑字段仍需同步核对依据。版本恢复执行当前结构与质量检查，并校验业务资料版本；业务条件变化或旧版本缺少资料基准时禁止恢复，需按当前资料重新改写。
- 单篇模型请求增加一次事实核对，失败时最多再改两次。候选已落盘可继续采用；服务重启会中断尚未完成的模型调用，需要重试，原文和已保存候选保留。
- 当前调整建议按目标与已记录结果提供检查方向，不能诊断平台算法或证明因果。跨行业、跨平台固定样本盲评与长期实际发布比较仍需持续积累；不依据单次模型样本宣称流量或成交已提升。

## 验证边界
