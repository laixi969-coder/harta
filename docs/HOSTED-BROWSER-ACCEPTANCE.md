# Harta 内置浏览器连接与抖音验收

更新：2026-10-10。用户选择优先采用浏览器路线，不要求普通用户安装插件，也不以开放平台应用审核作为网页登录前提。

## 已实现

- 平台账号页默认展示后台浏览器连接；官方 OAuth 与扩展连接收进折叠区域。
- 点击连接后，由 Harta 服务启动独立 Chromium 上下文，显示真实平台登录画面。二维码来自平台页面，不生成假二维码，也不调用逆向登录接口。
- 用户可在 Harta 内点击登录入口、刷新页面中的二维码、操作验证滑块。密码/短信输入尚不支持；当前面向平台 App 扫码流程。验证码由用户处理。
- 浏览器页面确认当前登录人的主页 ID 后，自动登记账号并绑定执行身份。昵称尚无统一可靠读取方式，未读到时显示账号 ID 尾号。
- 登录状态保存在 Harta 服务器的私有加密文件中；用户与业务隔离。前端和普通工作区 API 不返回 Cookie、令牌或浏览器存储内容。
- 每 10 秒检查已创建连接的任务，复用原有评论采集、发布、回复、私信、自动回复执行器。启动服务不会凭空创建平台账号。
- 发布和消息执行默认关闭，需在账号连接页开启；任务仍要求用户核对具体内容、接收人及可见范围。自动回复仅执行明确启用的规则。
- 提交前核对账号和任务，平台回执决定结果。未知结果暂停实际执行，不能自动重发。
- 断开会撤销后台通道、取消未提交任务、关闭浏览器并清除存储的登录状态。已经提交的操作不能撤回。

当前运行于这台电脑上的 Harta 服务进程，不代表已经部署到公网云服务器。多人商用部署还需浏览器运行环境、资源限额、持久化密钥和运维配置；当前最多同时运行 4 个浏览器上下文，每用户最多 3 个有效连接。

## 开发与运行

依赖：`playwright-core@1.59.1`，已加入 `package.json` 和 `bun.lock`。服务端需要安装 Chrome / Chromium。当前 Mac 使用已安装的 Google Chrome；可通过 `HARTA_BROWSER_EXECUTABLE` 指定其他官方 Chromium 可执行文件。

无浏览器时页面显示后台未就绪；启动失败时显示实际错误，不伪装扫码成功。不修改系统代理，不绕过验证码、证书错误或平台限制。

浏览器上下文彼此独立，只恢复当前连接的状态。`data/hosted-browser/` 使用 AES-256-GCM 加密、目录 700 / 文件 600。密钥与密文同机存储，不等同外部 KMS。断开后的历史任务结果保留用于核对，登录状态被清除。

页面导航限定对应平台主站 / 创作者站；请求域名受平台资源域名列表限制。若平台新增资源域名，需根据真实页面验证后维护列表。不要为了“能打开”放开内网请求或关闭浏览器安全隔离。

真实尝试记录：Chrome 直接访问抖音返回 `ERR_CONNECTION_CLOSED`；从已登录的 Harta 点击“扫码连接抖音”后，后台浏览器也返回同样的连接关闭错误。因此当前无法提供真实抖音二维码，没有进行任何真实平台发送或发布。不能把 DOM 测试页面通过写成真实抖音兼容性通过。

## 下一步真实验收顺序

1. 先恢复 Harta 服务所在电脑对抖音的正常访问；在 Harta → 平台账号中点“打开连接画面 / 重新打开登录页”。
2. 出现抖音真实二维码后，由用户使用自己的抖音 App 扫码；如平台要求验证，由用户完成。
3. 核对连接后显示的账号主页 ID；由用户提供其另一个测试账号主页链接。
4. 发布通用 Harta 功能测试视频，可见范围必须为“仅自己可见”；若平台不给私人发布可核对作品 ID，记录“平台已受理”，不冒充已发布。
5. 用用户控制的另一测试账号提供的作品及评论，验证采集和回复；仅自己可见的发布作品不默认能让另一个账号发表评论。
6. 向该测试账号发送一条明确的 Harta 功能测试私信，并核对平台回执。
7. 任何被平台限制或无法核对身份、接收人、可见范围的操作，停止并记录具体原因；不扩大到真实潜客批量发送。

## 测试入口

- `lib/hosted-browser.test.mjs`：租户隔离、登录状态加密、网络失败、任务领取、执行开关、未知结果不重试、断开与域名限制。
- `scripts/check-hosted-browser-runtime.mjs`：拦截全部目标页面为隔离 DOM，验证实际后台浏览器适配器的读取、提交及回读。不访问真实账号。
- `scripts/check-hosted-browser-ui.mjs`：无插件入口、权限、登录画面交互、开关、断开、错误与响应式布局。
- 原连接器、执行中心和官方扫码授权测试继续保留。
