# 双路径获客：实现与验收记录

更新：2026-10-08。需求依据为根目录 `prd.MD`。本次为现有 Harta 上的第一阶段辅助闭环，平台条件内自动执行尚未交付，不作为上线效果证明。

v0.3 续作：已补智能体配置／版本／知识引用／账号资料绑定／试运行／启停／复制／归档及记录，找客任务可固定引用已启用角色版本。新增单任务详情与导出，修正业务汇总范围、咨询账号联动及旧回复草稿提示。当前版本的详细验收与尚未覆盖的 PRD 要求见 `UI-UX-PRD-2026-10-08.md`；下文原 443 项为前一轮记录。

## 已实现

- **双路径获客首页**：待核实需求、待登记发布、已记录的待回复线索；优先跳转最早未处理咨询。
- **双路径获客 → 主动找客**：按业务选择，复用已配置的 SearXNG / Brave 公开搜索，或单条 / JSON 导入真实原文和原始链接。保存任务输入快照、查询、平台、读取范围、时间和来源。搜索结果明确标为摘要，未读站内评论。
- **任务**：立即启动、停止、重跑；服务端运行不依赖网页保持打开。逐平台保存成功与失败；失败不记为零；停止后不写入在途结果。服务重启后的未完成任务显示中断，已有结果保留。
- **需求核实**：规则辅助排序附理由，不是购买概率。保存人工核实 / 排除依据。作者回复不能建立新线索。同业务同平台记录 ID 去重；没有记录 ID 时仅按相同链接与原文避免重复导入。
- **线索与咨询**：独立于甲方客户表，保留需求证据、人工咨询原文、消息渠道与账号、发布来源、跟进历史、下一步和计划时间。支持来源 / 阶段筛选、分页与 JSON 导出。
- **身份与双路径触点**：同业务、同平台稳定用户 ID 可串联多条证据和咨询；同名昵称不自动合并。身份不明的相似对象可由用户在核实时选择已有线索，禁止跨业务、平台或不同稳定身份合并。主动与内容触点同时保留。
- **内容获客**：沿用已有内容生成、改稿、排期、导出和风险检查。可选原有内容与实际账号，核对完整文字后保存发布快照，再登记实际链接、时间和可选平台内容 ID。与历史“已发布”标记兼容；补录链接不会猜测旧版本。
- **回复**：模型配置可用时结合业务资料、读取附件、需求证据和会话生成草稿，并复用独立事实核对与行业限制。模型未配置时明确提供澄清模板。生成期间资料、会话或联系限制改变时拒绝过时结果。
- **发送状态**：草稿、已复制、人工登记已发送、取消分别保存。剪贴板权限失败不登记已复制；复制不清除待回复。新消息重新待回复；不同账号和渠道各自保留未回复状态。
- **联系限制**：人工接管、禁止联系与恢复均保留依据；禁止联系取消未发送草稿，并阻止生成、复制和登记发送。当前没有自动发送队列。
- **账号与连接**：按业务登记平台账号，明确只是人工处理标识。逐平台展示搜索、评论、发布、接收、发送未验证状态；不接收或暴露平台凭证。
- **线索页内的跟进与复盘**：按双路径展示已记录线索、待回复与人工成交阶段，可回查原文、来源任务、会话和发布版本。双路径交叉线索不相加为独立人数，不计算缺乏分母的转化率。

## 数据与 API

新对象保存于各销售已有工作区的 `acquisition` 下：`tasks`、`signals`、`leads`（含消息、跟进事件）、`publications`、`accounts`、`logs`。旧工作区读取时兼容空对象；现有工作区原子写入机制和账号鉴权继续使用。异步搜索写入前重新读取最新工作区，避免覆盖并发业务修改。

v0.3 增加 `agents`（含不可变 `versions`）和 `agentRuns`。知识引用在版本中保存业务 ID 与摘要哈希；试运行保存当时的知识、配置与原文。对外只支持 `analysis` 模式，账号绑定不授予平台收发权限。

- `POST /api/acquisition/agent-create|agent-save|agent-action`：创建／复制、乐观版本检查、启用／暂停／归档。
- `POST /api/acquisition/agent-trial`：返回 202，后台完成分析与草稿；统一 GET 查询状态。试运行不写入线索或发布记录。

- `GET /api/acquisition`：本人工作区与当前接入能力。
- `POST /api/acquisition/import|search|stop|review`：需求、任务、核实。
- `POST /api/acquisition/account|prepare-publication|publication`：人工账号标识、发布快照与事实登记。
- `POST /api/acquisition/inquiry|lead|suggestion`：咨询、跟进 / 草稿 / 联系限制、辅助回复。

所有 ID 都在当前登录账号名下解析。管理员不增加读取其他销售记录的权限。用户提交的来源只作为文本和链接，不执行其中的指令，不根据昵称推造联系方式。搜索与模型生成使用原有限流和并发保护。

发布状态当前实际可达：待登记发布 → 人工登记已发布 / 已取消。排队、执行中、平台提交待核实、结果不明等自动发布状态，须在执行连接器接通后补齐，不以手工登记代替实现。

## 尚未实现或尚未联调

| 项目 | 当前边界 / 后续条件 |
| --- | --- |
| 小红书、抖音站内搜索与评论读取 | 公开摘要和用户导入可用；需官方权限或独立浏览器连接服务及账号级测试 |
| 自动发布、发布结果核实 | 本次提供不可变快照与人工登记；需要真实执行器、素材上传、平台回读与幂等确认 |
| 自动同步评论 / 私信、自动回复 | 本次人工咨询登记与草稿辅助；需要消息事件、真实接收对象和发送权限 |
| 浏览器登录隔离、离线 / 验证码暂停 | 尚未部署连接器；不能将“登记账号”当作登录成功 |
| 定时找客、自动发布任务调度 | 搜索支持立即、停止、重跑；现有内容排期仍是人工待发布提醒 |
| 扩平台与策略效果优化 | 其他平台可登记手工证据和账号，自动能力未接入；不凭缺失或不可比数据判断效果 |
| 真实账号效果验收 | 本次测试使用隔离夹具，没有替用户执行真实发布或联系他人；没有宣称真实获客效果 |

本次没有引入 MediaCrawler、Postiz 或其他第三方平台执行代码。

## 验证

- `npm test`：46 个测试文件、443 项测试通过，含 18 项新增获客业务测试；HTTP 安全测试额外覆盖未登录、跨销售需求 ID、账号归属与能力状态。
- `scripts/check-acquisition-ui.mjs`：在临时目录启动服务，以隔离测试账号实际操作导入、核实、登记账号、生成澄清草稿、保存回复、发布快照、关联咨询、保存跟进；所有临时业务数据在结束后删除。
- 浏览器检查：桌面 1440px，窄屏 390px；深浅主题文字 / 控件对比度；无横向溢出；无页面脚本异常。闭合 details 的不可见内容不计入可见对比度检查。
- 新视图沿用现有色彩和字体，主标题 32px、正文 16px、操作目标至少 44px；不增加装饰动画，减少动态效果偏好下禁用过渡。

运行浏览器验收需要已安装的 Playwright。可使用项目环境中的 `playwright`，或设置 `HARTA_PLAYWRIGHT_MODULE` 为现有安装的模块绝对路径。默认截图写入系统临时目录，可用 `HARTA_UI_OUTPUT` 指定输出目录。

## 保留旧功能与页面（用户确认）

原有今天、客户、客户报告、跟进记录、全组和设置页面保留原布局与操作。双路径待办、平台账号和新复盘模块归入新增页面，不占用旧页面顶部。原“标记整条已发布”继续一键记录，不要求填写链接或账号；“登记发布链接 / 版本”为独立可选入口。旧记录不删除、不迁移、不自动补造发布版本。浏览器验收同时覆盖旧按钮行为及新增模块不会进入旧页面。
