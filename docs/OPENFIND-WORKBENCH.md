## 实现与运行

- 上游源码：`vendor/openfind/src/`、`server/`、`shared/`、`public/`；完整适配说明见 `vendor/openfind/NOTICE.md`。
- `bun install --frozen-lockfile` 后可直接 `node server.mjs`，已提交可运行的构建产物；改前端后运行 `bun run build:openfind`。类型检查：`bun run check:openfind`。
- 工作台：`/openfind?customerId=<业务ID>`；接口：`/api/openfind/workbench/<业务ID>/...`。所有业务数据接口先检查 Harta 登录与业务归属，再按方法/路径白名单转发。内部令牌、Harta 会话 Cookie 不转发给平台或回传前端。
- 每业务独立进程、SQLite、Chrome 配置、凭证密钥与上传目录，仍最多同时运行三个业务。关闭引擎后后台读取不会自行重新打开；重新进入工作台或明确操作可启动。
- 媒体仅读取当前业务保存的素材与两平台公开 CDN；旧 HTTP CDN 链接升级为 HTTPS，公网 DNS/CONNECT 保留 TLS 验证，拒绝重定向与本地目标；图片限 16MB、缓存有上限。自定义适配器须返回支持的平台媒体域名。
- API 白名单契约测试覆盖上游主路由及新增销售路由，减少未来更新只接到部分端点的情况。模型复核转发时限兼容上游最长 3600 秒设置。

- 上游/适配检查：55 项通过，包含模型密钥加密、模型列表/测试、语义引用与线程证据、时限、销售阶段/订单依据及拒绝联系。
- 浏览器真实验收：小红书 15 张已有作品封面全部加载；详情两张图片可切换，正文和原始发表时间补全。下载批量 ZIP 并解包核对两张 WebP 和正文；克隆编辑、图片换序、仅自己可见、本地保存与预览通过。草稿 ZIP 解包同样包含实际图片及正文。
- 新完整工作台再次实测：抖音搜索及历史发现形成 21 篇候选，采样 1 篇读取 2 条评论，完成规则复核；小红书先以 1 条搜索观察到零评论作品并如实保留零采样，再扩大至 5 篇，采样 1 篇读取 2 条评论并完成。结果自动同步，无手动导入。
- 目前该业务 91 条真实作品均有封面；原有两条 Harta 客户的需求证据、阶段和跟进时间保留。OpenFind 真实询价线索可跳到已有待核实客户；销售模块带入 Harta 真实业务资料并以明确标记的内部验收备注验证同步，不登记虚构客户回复或成交。
- 共享模型除隔离协议检查外，已使用 Harta 当前模型完成真实 JSON 生成和抖音评论复核：12 条原始评论，本地排除 4 条，8 条保存可核对的模型引用；小红书 45 条评论本地排除 17 条，28 条保存有效模型结果。两端合计 57 条评论、36 条有效模型证据，候选及已有跟进记录保留。引用或结构不合规时最多纠正一次，两次均执行相同校验；失败保留本地规则和已完成批次。官方发布/预览/回执功能已接入，本轮未向真实平台发布内容或发送消息。
