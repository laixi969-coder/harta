# 2026-10-23 工程审查修复

## 行为变化

1. 客户网页抓取在 socket DNS lookup 阶段检查所有解析结果，拒绝私网地址；每次跳转继续验证 URL，连接时继续验证地址。不会把预检查通过的域名直接交给未受控解析器。
2. `/api/openfind/workbench/:business/request-budget` 的 PUT 只允许管理员。普通用户可读取预算。资料分析进入独立业务预算；所有模型 POST（包含测试、视觉回退和云语音）还经过跨进程持久化的账号及全服务费用预留/次数上限。
3. `data/llm.json` 内的 apiKey 使用 AES-256-GCM 加密，密钥保存在 `.model-key`。启动时迁移旧配置，原子替换；data 为0700，配置与密钥为0600。缺失/错误密钥时拒绝解密，不自动替换。完整备份包含密钥并验证能解密。该措施不能防止已经拥有同一系统用户权限的程序；磁盘加密仍由操作系统负责。
4. 上传文件在独立 Node 进程中解析，JS堆256MB、总时限3分钟；Unix子进程继承90秒CPU及文件大小限制，外部转换器另有90秒期限。超时回收整个进程组后再清临时目录。该隔离不等于抵御原生解析器任意代码执行的完整OS沙箱，不含商业病毒扫描。可疑大文件应拆分，服务器宜使用专用受限系统账号。
5. 报告默认不再自动发布。登录用户可始终预览自己的报告；“生成7天分享链接”产生新令牌并使旧令牌失效，可主动撤销。过期、所有者停用/密码被重设均不可匿名访问。升级前的旧链接失效，须主动重建。停用或重设密码会改变分享授权版本，即使重新启用账号，旧分享也不会恢复。
6. 新建资料需要勾选外发授权，补充上传需要确认；服务端要求对应协议标识，批次记录确认时间和账号。确认涵盖正文、图片和语音，提示不得提交未经授权的个人/患者数据。此机制不能识别所有敏感信息，不能替代客户授权、供应商协议或脱敏；确认后原始图片及语音仍会外发。模型系统提示明确把材料视为数据，不能宣称完全消除提示注入。
7. 一个账号最多占用2个获客引擎，全局仍为3个。没有任务和定时采集的引擎10分钟空闲后释放。正在运行或配置了定时任务的业务不因空闲回收而中断。需要更多容量时仍需明确规划。
8. 删除跨全部来源的登录/注册共享封禁桶。登录改为来源IP+邮箱8次/10分钟，另保留每IP60次/分钟上限；注册保留每IP5次/10分钟。单个邮箱的错误尝试不会立即耗尽同出口其他邮箱的8次额度。分布式DDoS仍需要边缘防护。
9. 分享令牌通过独立索引直接定位一个工作区；不存在的令牌不会扫描其他账号。备份不保留分享索引，恢复后旧分享不可用，报告中对应分享状态也被清除。
10. 新增 `npm start` 托管启动。超过24小时没有成功备份时，先正常停止应用，再建立离线备份，在新目录试恢复并检查凭证/数据库，成功才记录状态；保留最近7份。失败记录错误、恢复服务，最多每小时重试。原生launchd启动脚本已改用托管启动。`npm run dev`/直接运行server不含自动备份。

## 模型费用参数

以下环境变量只能由部署管理员设置；金额为美元分，按UTC日计数，所有尝试提前预留，不因失败退款。

| 参数 | 默认 | 含义 |
|---|---:|---|
| HARTA_MODEL_ACCOUNT_DAILY_CENTS | 1000 | 每账号每日预留上限，10美元 |
| HARTA_MODEL_TOTAL_DAILY_CENTS | 10000 | 全服务每日预留上限，100美元 |
| HARTA_MODEL_ACCOUNT_DAILY_CALLS | 100 | 每账号每日模型POST次数 |
| HARTA_MODEL_TOTAL_DAILY_CALLS | 1000 | 全服务每日模型POST次数 |
| HARTA_MODEL_INPUT_CENTS_PER_MILLION | 1000 | 输入价格上界，美元分/百万token |
| HARTA_MODEL_OUTPUT_CENTS_PER_MILLION | 5000 | 输出价格上界，美元分/百万token |
| HARTA_MODEL_IMAGE_TOKEN_BOUND | 16384 | 单张图片输入token预留上界 |
| HARTA_MODEL_AUDIO_CENTS_PER_MINUTE | 10 | PCM WAV每分钟费用预留上界，美元分 |

这是保守预留账本，不是供应商账单对账。普通文本按UTF-8字节数保守预留；图片按每张16384 token上界预留；语音按实际PCM WAV时长每分钟10美分预留，不再把Base64当成文本计价。输出按max_tokens预留（没有值时按8000）；最高32000，单次请求体最高32MB。必须根据所用模型核对价格上界是否覆盖真实收费和附加费；不能保证未知供应商收费、按工具/图片计费或价格变化永远低于估计值。需要实际付款硬封顶时，同时配置供应商账户限额。费用账本位于 `data/model-spend.sqlite`，不保存提示词或原始邮箱。

## 备份与运行

默认目录：`~/.harta-backups/Harta`，可通过 `HARTA_BACKUP_DIR` 指向其他磁盘/挂载的备份目录。备份根目录必须在业务data之外。默认同机副本不能防整机或硬盘丢失；未配置异地存储时不能宣称已有异地灾备。

托管启动会在首次运行时备份，以后每24小时备份；备份前通过私有IPC检查HTTP请求、内容任务、销售草稿和采集任务，忙时自动延后，不强制中断进行中的工作；空闲后短暂停机生成一致快照。任务持续繁忙时备份会延迟，status.json记录原因。大数据量需要更长维护时间。备份成功时间、恢复验证结果或最近失败原因在备份目录 `status.json`，失败也写服务错误日志。没有配置短信/邮件外部告警。

手工命令保持不变：

```sh
node scripts/harta-backup.mjs create /绝对路径/data /绝对路径/新备份目录 --offline
node scripts/harta-backup.mjs restore /绝对路径/备份目录 /绝对路径/新恢复目录
```

恢复仅写新路径，不覆盖当前业务。完整备份必须同时保留 `.model-key`、各业务 `.credential-key` 和对应配置/数据库。新加密格式不兼容旧代码，回滚需要同时恢复匹配的升级前备份，不能只回退代码。
