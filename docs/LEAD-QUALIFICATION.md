# 客户线索分级与跟进

在「客户跟进」选择联系人。有多次购买需求时，先选要评定的那一笔。展开「评定线索」，核对业务适配、客户需求和客户已同意的下一步，选择客户来信、已核实评论、销售记录或填写实际沟通时间及人工依据。评论缺少发布时间时需补录实际沟通时间。保存前可看到预计等级。

## 默认标准

| 等级 | 判断条件 | 下一步 |
| --- | --- | --- |
| A | 业务能承接、客户需求具体，并已有本业务认可的推进约定 | 落实约定，记录下一步和时间 |
| B | 已有具体需求或明确的推进约定，三项 A 级条件尚未齐全 | 补齐适配条件、需求或客户意愿中缺失的一项 |
| C | 客户明确表示只做初步了解或长期储备，尚无具体约定 | 记录关心的问题，等客户出现具体需求 |
| 待核实 | 缺少足够事实，例如只有昵称、一次泛泛问价或销售人员自行发出的报价 | 回看原话再评定 |
| 不适配 | 已核实客户条件超出产品或服务的承接范围 | 保存原因，条件变化后复核 |

购买咨询、商务合作、私域承接和售后服务可分别登记和筛选。同一人可有多种事项。成交、结束、暂缓、售后和停止联系各有状态。售后仍可进入待回复，明确拒绝联系会停止营销跟进。

适配和客户参与程度是两个独立的判断维度。Harta 采用上表中的业务规则，已有销售记录同时核实了需求和时间时可直接归 B。评论初筛分、关键词热度、商家的报价和成交金额不会单独产生 A 级。[HubSpot 对适配与参与程度的说明](https://knowledge.hubspot.com/scoring/understand-the-lead-scoring-tool)

## 每个业务怎样设标准

在「客户跟进 → 本业务分级标准 → 调整标准」填写承接范围与交付条件，选择哪些客户约定可以计入 A 级，再设定复核周期。默认接受预约、约定报价、确认打样或订购、确认商务简报或提案，默认复核周期为 30 天。

| 业务示例 | 可采用的适配与推进条件 | 判断结果 |
| --- | --- | --- |
| 音乐教育 | 校区和课程适合孩子，家长确认周六到校试听 | A；若该业务调整为仅接受正式采购约定，则按新标准重算，提示复核 |
| 厨房收纳 | 确认半年后装修，目前只收集尺寸；另一位客户需要上门量尺、地址超出覆盖区 | 前者 C，后者不适配 |
| 电商采购 | 旧单已成交，售后处理退货；同一客户为新订单确认规格、数量及打样 | 新采购 A，旧单及售后分别保留 |

## 排期与复盘

- 在「客户跟进」可组合筛选等级、咨询类型、姓名或平台账号。选「待复核」可查到依据过期、有新客户依据、业务标准变化、产品或规格变化、原评论被排除的事项。
- 在 A、B 级详情点「安排下一步」可登记事项和时间。「经营总览 → 今天值得处理」优先列出待回复与到期事项，提醒 A 级安排时间。已有未来排期的 A 级按约定时间处理。
- 点「重新评定」可更正判断，点「撤销评定」可清除当前判断。「分级记录」保留当时的等级、标准、依据、时间和原话。建立购买需求前的联系人评定可回查，每笔新购买需求从自己的依据开始。
- 「全部业务结果」按平台稳定身份统计当前分级人数。「按结束前的等级看购买需求」逐笔统计成交和结束未成交，取结束前最后有效的评定。历史订单缺少当时记录、评定已过期等情形列为「无有效评定」。重新打开的需求会移出这张表。
- 主动获客的已入库线索、历史会话和跟进记录导出可回查分级。日常评定、排期和复盘均在 Harta 内完成，无需填写模型或数据源 API Key。

## 验收

规则和数据写入覆盖分级边界、三类业务、证据归属和撤销、并发更新、跨业务隔离、产品变化、旧订单、停止联系与成交前分级。浏览器验收使用隔离的示例工作区，实际提交表单并重新加载，覆盖手机筛选与跨时区排期。

```sh
npm run check
node scripts/check-lead-qualification-ui.mjs
```

## 有效联系人与批次效率

经营总览按本业务当前有效评定统计联系人。默认要求已核实适配、具体需求，以及业务认可的推进约定。可在「客户跟进 → 本业务分级标准 → 调整标准」改为已核实适配和具体需求。规则改版、依据过期或撤销后可在跟进页复核。有实际联系记录的人数单独展示。

在「主动截流 → 更多操作 → 批量采集」选一个已完成的真实批次，展开「查看批次效率与抽样核对」。已有请求账本、可关联本批且仍符合条件的新增联系人、首次核实用时会直接显示，整批人工分钟可单独补记。同一联系人只归到最早有对应原评论的批次，已有联系人与身份记录不完整的历史数据不能确认为本批新增。零结果保留总投入，历史未跟踪的用量显示为未记录。

可选抽样把两种排序的前十与最多五条共同排除项混排。每项判断会自动保存。全部处理后可看对照、原话和筛选依据。匿名导出只含随机编号、排名和人工判断，三个文件采用 TREC 的 qrels/run 文本格式。「依据不足」保留为未判定。排序盲核评的是相关需求，正式有效客资仍按跟进页核实记录计数。新批次冻结当时的样本，历史批次可按保存记录回放。

隔离验收可运行 `node scripts/check-batch-review-ui.mjs`，从桌面总览和手机尺寸批量获客面板核对实际操作。
