# Harta 主动销售沟通优化

本轮目标：围绕其他账号中已经核实的真实需求，帮助用户开场、获取下一条有效信息、匹配产品、处理顾虑并推进真实成交。原有内容创作、研究和报告仍可使用。

## 已实现

- 销售策略运行时：首次沟通、需求澄清、产品匹配、异议处理、成交推进和适度跟进。按本次需求的实际会话选择；老客的新需求独立处理。策略版本随草稿保存。
- 产品与服务下的销售知识库：可保存 FAQ、使用说明与可对外使用的案例，指定业务通用／产品／SKU 范围、来源、确认状态和有效期。未确认、停用、过期或不在范围内的资料不会进入起草。当前使用本地中文双字词和英文词检索，最多提供五段带原始位置的片段。
- 报价精确读取：无规格产品／服务使用自身已确认价格；有规格产品使用所选规格价格。报价可设置有效期。历史报价保留，过期价格从当前生成范围中排除，旧草稿复制时重新核验。资料中匹配到的数字不能授权报价。
- 生成、检查和修正：草稿先通过确定性报价与承诺检查，再通过模型事实核对。事实核对也检查是否回答当前问题，以及是否把客户要求误当成产品能力、把未知政策说成“没有优惠”。有可定位问题时仅修正一次，修正后运行同样的检查；仍有问题则不产出可复制草稿。
- 草稿旁可查看沟通目标、策略依据、待确认条件、下一步与本轮提供的资料。这里展示的是提供给模型的依据，不声称每条片段都被正文实际引用。模型未配置时明确显示澄清模板。
- 首页销售跟进队列：待回复、到期跟进、待开场，点击直接打开对应联系人的具体购买需求；不会把联系人阶段或历史成交覆盖成新需求阶段。
- 联系控制：拒绝联系跨本联系人的不同需求生效；中性回复不自动撤销拒绝。要求人工或明确售后办理时停止主动销售建议。已联系未满 24 小时且未收到回复时暂缓；无回复最多再跟进一次。统计实际人工登记发送，不把复制当发送，不把回复当成交。

## 来源与组件选择

销售方法依据调研中选定的 Anthropic 销售技能与 practical-ai-sales-workflows 做了中文评论／私信场景的改编，来源、固定提交和许可证保存在 `vendor/sales-methods/`。不执行上游插件的 CRM／邮件操作指令。

本轮落地轻量本地检索，没有引入 LanceDB，也没有向量 embedding 或独立知识平台。小目录先保证范围、版本和报价可核验；同义词和复杂语义召回仍有限，大规模文档可在这些服务端过滤规则下更换检索后端。当前每业务最多 200 份资料、单份 30000 字。

Promptfoo 固定使用 0.124.1，作为开发期按需运行的工具；不是线上服务依赖。其自定义 provider 直接调用生产的策略、资料过滤、生成和复核模块，不另写一套测试专用提示词。规则模式不调用模型；真实模式使用 Harta 已配置的模型，输入均为合成灯具场景，不读取真实客户资料。

## 对抗式审查与修复

| 风险 | 处理 |
| --- | --- |
| 其他业务／产品／SKU 的相似资料串入 | 检索之前做范围过滤，未选 SKU 不取 SKU 专属资料 |
| 文档注入要求改成 888 元、虚报已下单 | 资料作为不可信数据；价格精确检查及事实复核，模型无发送工具 |
| 24 个月保修里的数字被用于 24 元报价 | 价格检查只认价格条件中的金额，不认任意数字 |
| 客户要求免打孔，被当成产品免打孔 | 明确区分需求证据与产品事实，事实失败修正并再次复核 |
| 本次仅选一个产品，就说全店只有一款 | 写入系统约束及确定性检查；所选范围不代表完整目录 |
| 拒绝后换账号、换需求或补一条“谢谢”继续营销 | 联系人范围检查拒绝，只有人工有依据地恢复联系才解除 |
| 已发两条仍不断追问 | 按真实发送时间与最新收到消息计算冷却和未答复次数 |
| 生成途中更新知识、接管或收到新消息 | 生成结束重新比较当前上下文，丢弃过时结果 |
| 资料／报价在草稿完成后到期 | 复制前重新核对资料与产品范围哈希 |
| 新增知识表单在业务切换时混草稿 | 业务独立草稿键；产品变更后同步重建规格选择 |

## 验证与范围限制

自动化结果见本文件后续验收记录。真实模型场景评测是单批样本，不代表“顶尖销售”、稳定通过率或实际成交提升。早期评测发现客户要求被误当成产品能力、把未知优惠政策说成没有优惠等问题，已据此修改提示与复核流程；人工审阅仍是发送前的一步。

主动平台读取、接收和发送仍未接通。本轮不会自动联系外部客户，也不会自动创建订单、收款或标记成交。界面保留明确的草稿、人工实际发送记录和未接通状态。

## 复现

- `npm test`：规则、数据与 HTTP 权限回归。
- `npm run eval:sales`：Promptfoo 合成规则场景。
- `HARTA_SALES_EVAL_LIVE=1 npm run eval:sales`：真实模型生成与复核，会调用当前配置的模型服务。
- `HARTA_PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs node scripts/check-commerce-ui.mjs`：隔离临时工作区的页面验收。

Promptfoo 只记录自定义 provider 的请求次数，本接入未上报 token／费用；报告中的零 token 不表示模型调用免费。

## 最终验收记录

- `npm test`：50 个文件、505 个测试通过。
- Promptfoo 规则模式：10/10 通过。最终真实模型模式：10/10 通过，其中 8 个场景生成并复核草稿，2 个场景在调用模型前停止营销。真实模型早期批次暴露了事实错误，增加修正与确定性约束后重新验收；这不是跨模型或长期稳定率测试。
- 两条隔离 Playwright 流程通过：新销售／产品／评论／会话流程，以及原获客、发布、咨询、智能体流程。深浅主题对比度、新界面 320／375／414／768px 溢出检查和脚本错误检查通过。
- 人工阅读最后一批合成草稿，确认有对当前问题的回应、对未知条件的核对表达；未将客户“免打孔”的要求作为本产品已具备的事实。
- CSS 静态检查 P0=0。检测器对 JS 模板里的动态 `url` 报告了假阳性，不是本地文件引用；已有 URL 校验和浏览器流程确认。其余提示是楼中楼层级边线、兼容旧样式的 `--paper-shadow` token，不是新增装饰。
- 实际截图和模型评测结果保存在本地 `output/sales-ui/`、`output/research/sales-eval-*.json`，未将本地输出目录整体提交。
